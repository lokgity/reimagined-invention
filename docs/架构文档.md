# 浙江省商铺选址 AI Agent —— 项目架构文档

> 2026 iCAN 大学生创新创业大赛 · AI 应用创新挑战赛
> 定位：面向个人创业者的"选址决策顾问"，而非数据工具

---

## 1. 项目定位（一句话）

**美团/高德是给"看得懂数据的人"用的工具，我们是给"看不懂数据的人"做判断的顾问。**

- 美团/高德：输出数据看板、指数 → 用户自己判断
- 我们：输出"该不该开 + 为什么" → 直接可执行，且解释每个判断的理由

## 2. 差异化核心（答辩话术）

| 维度 | 美团/高德 | 本项目 Agent | 价值 |
|---|---|---|---|
| 交互 | 地图+筛选器 | 说人话对话："我想在下沙开奶茶店，月租8千" | 零学习成本 |
| 需求梳理 | 用户自己填 | 多轮反问："客群是学生还是白领？堂食还是外卖？" | 帮用户理清需求 |
| 输出 | 数据看板 | 结论+理由+"该不该开" | 直接可执行 |
| 主动质疑 | 从不质疑 | "这位置品类错配，建议换临街位" | 帮用户避坑 |
| 可解释性 | 指数不透明 | 经济学原理解释每个判断 | 授人以渔 |
| 成本 | 付费订阅 | 免费/极低价 | 服务被排除在外的个体创业者 |

**黄金句式**："我们的 agent 不是数据的搬运工，是决策的解释器。"

## 3. 范围界定

- **地域**：浙江省全境（11 个地级市）
- **品类**：奶茶、甜品、早餐、便利店（4 类，共享评分框架 + 品类画像参数）
- **明确不做**：精确人流量（无数据）、营业额预测（不承诺精度）、全国覆盖

## 4. 系统架构

```
┌──────────────────────────────────────────────────┐
│  界面层: Chainlit（对话式 Web 界面 + 右侧工作台）     │
│   - 输入: 城市+品类+候选地址(2~3个)+前期投入          │
│   - 输出: 5 维度评分 + 盈利测算 + 一票否决 + 对比报告  │
├──────────────────────────────────────────────────┤
│  Agent 层: 大模型 API（DeepSeek/通义, 工具调用）     │
│   - 多轮追问需求（预算/客群/品类/面积/堂食外卖）       │
│   - 调用评分引擎获取真实数据                        │
│   - 生成推理链: "为什么 72 分 / 为什么建议避开"       │
│   - 主动质疑: 识别品类-位置错配                     │
├──────────────────────────────────────────────────┤
│  评分引擎: 通用框架 + 4 份品类画像参数               │
│   - 客群匹配度 / 竞争压力 / 交通可达性 / 租金承受力    │
│   - 每个品类: 目标客群关键词 + 权重 + 参考半径        │
│   - 经济学依据: Huff 引力模型 / 商圈理论 / 中心地理论  │
├──────────────────────────────────────────────────┤
│  数据层: 高德开放平台 POI/周边搜索                   │
│   - 预抓取浙江省 11 市 × 4 品类 POI → 本地 SQLite    │
│   - 演示纯离线, 不依赖现场网络/API 限流              │
└──────────────────────────────────────────────────┘
```

## 5. 数据层设计

### 5.1 数据源

| 数据 | 来源 | 用途 |
|---|---|---|
| 竞品 POI（奶茶店/甜品店/早餐店/便利店） | 高德 POI 搜索 | 竞争压力、客群线索 |
| 配套 POI（学校/写字楼/小区/地铁站/商场） | 高德 POI 搜索 | 客群匹配度、交通可达 |
| 行政区划/商圈 | 高德行政区查询 | 归属判断 |
| 租金 | 用户输入（预算是多少） | 租金承受力（不采集, 让用户给） |

### 5.2 预抓取策略

- 按 11 个地级市 + 关键词分片抓取，落 SQLite 表
- 表结构：`poi(id, city, district, category, name, address, lng, lat, type, pname, cityname, adname)`
- 抓取时同时拉配套 POI（学校/写字楼/小区/地铁/商场/医院）
- 增量更新：可定期重跑脚本刷新

### 5.3 为什么不用实时 API

- 演示现场网络/限流不可控 → 预抓取保证演示稳定
- 单次 API 有配额限制 → 批量离线抓取更高效
- 数据本地化 → 响应速度快（毫秒级 vs 秒级）

## 6. 评分引擎设计

### 6.1 四维度通用框架（0~100 分）

| 维度 | 含义 | 数据来源 | 经济学依据 |
|---|---|---|---|
| 客群匹配度 | 周边客群是否对应该品类目标客群 | 学校/写字楼/小区/商场 POI 密度 | 商圈理论 |
| 竞争压力 | 同品类密度 vs 区域均值 | 竞品 POI 密度 | 市场饱和度 |
| 交通可达性 | 地铁/公交可达性、人流动线 | 地铁站/公交站 POI 距离 | 交通区位理论 |
| 租金承受力 | 预估月流水 vs 预算租金 | 用户输入租金 + 品类参考数据 | 盈亏平衡分析 |

### 6.2 品类画像（参数表, 见品类画像文档）

每个品类定义：
- 目标客群关键词（用于客群匹配度）
- 各维度权重
- 参考半径（周边 500m/1km）
- 竞争密度基准值（多少家算饱和）

### 6.3 输出

- 每个地址 4 维度分数 + 总分
- 一句话结论（推荐/谨慎/不建议）
- 推理链（每个分数的关键证据）

## 7. Agent 层设计

### 7.1 对话流程

1. **需求收集**（多轮追问）
   - 品类？（奶茶/甜品/早餐/便利店）
   - 城市/区/具体地址？（支持地图选点或文本）
   - 预算租金？
   - 客群定位？（学生/白领/社区/流动）
   - 堂食为主还是外卖为主？
   - 面积、营业时间？（可选）
2. **数据获取**：调用评分引擎（工具调用）
3. **分析输出**：
   - 每个候选地址评分
   - 对比结论（哪个最优/都不合适）
   - 可解释理由（引用具体 POI 证据）
4. **主动质疑**：
   - 品类-位置错配检测
   - 竞争饱和警告
   - 租金风险提示
5. **Follow-up**：支持"换成咖啡店呢？""租金加 20% 呢？"

### 7.2 提示词要点（防套壳, 防幻觉）

- 所有判断必须引用真实 POI 数据（工具返回的），禁止编造
- 无数据支撑的判断必须声明"基于公开 POI 数据，未包含真实人流量"
- 评分数字必须来自评分引擎, agent 只做解读, 不自己造分

## 8. 界面层设计（Chainlit）

Chainlit 是唯一入口（早期的 Streamlit 版已下线，两套实现口径不一致会互相打脸）。

- 左侧：多轮对话（自然语言，支持一句话复合提问）
- 右侧工作台（`public/sidebar.js` 自研渲染，非第三方组件）：
  评分卡 / 五维雷达图 / 盈利测算表 / 关键证据表 / 周边热力图 / 风险警告
- 对话流内嵌：推理链事件（思考 / 工具调用 / 输入输出）逐步展开，可折叠
- 候选商铺卡片可点击选择；历史分析可勾选 2~4 个做全方位对比
- 一键导出 PDF 报告（Playwright 渲染，0 次额外 API）

结论口径为**双轴**：位置分结论（纯五维加权）与综合结论（含盈利一票否决）分开展示，
避免出现"总分 80.9 判推荐、AI 却劝你别签"的自相矛盾。

## 9. 项目结构

```
site-selection-agent/
├── requirements.txt
├── .env                    # API keys (不入库)
├── README.md
├── chainlit.md             # 对话页欢迎文案
├── public/                 # 前端静态资源（工作台渲染 / 样式）
├── src/
│   ├── config.py           # 配置(品类画像参数/API key加载)
│   ├── data/
│   │   ├── fetch_poi.py    # 高德 POI 抓取（限速 / 幂等 / 磁盘缓存）
│   │   ├── fetch_around.py # 周边搜索抓取
│   │   └── query.py        # SQLite 查询接口
│   ├── engine/             # 确定性评分层：同一输入同一结果，不依赖 LLM
│   │   ├── scoring.py      # 真 Huff 捕获份额 + 盈利一票否决 + 租金临界点反解
│   │   ├── utilities.py    # 水电 / 成本 / 净利 / 回本测算
│   │   ├── brands.py       # 连锁品牌系数 + 加盟政策参考
│   │   ├── negotiation.py  # AI① 租金谈判证据包（58 行情 × 承受力上限）
│   │   ├── competitor_insight.py # AI④ 竞品口碑画像（高德公开字段）
│   │   └── realtime.py     # 实时周边搜索兜底
│   ├── agent/
│   │   ├── agent_graph.py  # LangGraph 多阶段决策流（对话编排）
│   │   ├── agent.py        # 领域逻辑层（口语抽取 / 地理编码 / 规则兜底解读）
│   │   ├── state.py        # 图状态定义
│   │   ├── llm.py          # 多模型 LLM 调用 / 会话内切换
│   │   ├── vision.py       # AI③ 门头照 VLM 视觉分析
│   │   ├── knowledge.py    # AI② 选址知识库（RAG 检索）
│   │   ├── rental58.py     # 58同城真实在租店铺抓取
│   │   ├── analysis_store.py / conversation_store.py  # 持久化
│   ├── analysis/           # 模型标定与回归（λ / 锚点 / 敏感性 / 端到端测试）
│   └── ui/
│       ├── app_chainlit.py # Chainlit 界面（唯一入口）
│       └── report_pdf.py   # PDF 报告导出
└── data/
    └── zj_poi.db           # 本地 SQLite
```

分工原则：**引擎产数、LLM 产文**。所有数字由 engine 层确定性算出，LLM 只负责
组织成口语化解读，prompt 中明令禁止编造引擎数据之外的任何数字（包括行业经验百分比）。

## 10. 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Python 3.14 | 已有环境 |
| 数据 | SQLite（标准库 sqlite3） | 零部署；未引入 pandas，避免无谓重依赖 |
| 地图数据 | 高德开放平台（POI/周边/地理编码） | 免费额度, 覆盖好 |
| LLM | 火山方舟（Doubao-Seed-2.1 / DeepSeek-V4-Flash，会话内可切换）+ 备用链 | 中文好, 便宜；主链失败自动降级，规则兜底解读保证演示不崩 |
| VLM | 视觉模型（门头照分析） | 多模态证据，与文本链路解耦 |
| Agent 编排 | LangGraph | 多阶段决策流可显式建图，比 while 循环可解释 |
| 界面 | Chainlit + 自研 sidebar.js 工作台 | 原生流式对话；工作台自己渲染，评分卡/雷达图口径完全可控 |
| 报告导出 | Playwright（HTML → PDF） | 复用系统 Chrome，中文渲染无需额外字体库 |
