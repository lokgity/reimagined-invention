应用方案文档

01项目背景：一个关于"选择"的故事

2022 年春天，老家的小姨动了开店的念头。

她在县城一家工厂做了十一年流水线，攒下二十万积蓄。孩子要上初中了，她想在镇上开一家奶茶店，"既能照顾家，又不用再看老板脸色"。

选铺子的那一个月，她跑遍了镇上每一条街：在步行街口数了一下午的人头，周末人多得走不动道，她觉得"就是这儿了"；中介拍着胸脯说"这是全城最好的位置，租下来稳赚"。她没敢问租金占流水比，也不懂什么客群密度，更不知道步行街两百米外，已经有两家奶茶品牌在装修。

2022 年 6 月，她签下租约，月租八千八，押三付一，加上装修设备，二十万见了底。前三个月生意确实不错——但她不知道，那正是暑假学生流量的短暂红利。

2022 年 10 月，两百米内的第三家奶茶店开业。客流被摊薄，月租却一分不减。到了 2023 年春天，她已经连续五个月入不敷出，最终在 2023 年 6 月关店转让。设备折旧、违约金、转让折价，二十万只剩回四万多。

她至今不愿再提"开店"两个字。而这样的故事，在中国每年都在上演成千上万次。

我们团队在调研中反复听到类似的故事。我们发现，这些失败几乎都不是因为"不会经营"，而是因为"选错了位置"——而"选位置"这件事，普通创业者从来没有掌握过科学的工具。

1.1 行业的真实痛点

  • 数据分散：租金、客流、竞品、通勤配套散落在不同平台，普通人无从整合分析；
  • 经验难传：选址决策依赖"老师傅直觉"，不可复制、不可解释、无法验证；
  • 信息不对称：创业者缺乏专业工具，极易被中介话术与虚假客流误导；
  • 决策无依据：缺少可量化的评分体系与多方案横向对比能力；
  • 试错成本极高：一次选址失误，轻则数万装修打水漂，重则耗尽全部积蓄。

1.2 我们的答案

我们相信：选址不应该是一门玄学，而应该是一门可以被解释、被对比、被复现的科学。

浙里选址 —— 一个由大语言模型驱动的商铺选址智能体。用户只需用一句自然语言描述"想开什么店、开在哪里"，智能体便能自动完成：理解意图 → 抓取真实数据 → 科学评分 → 盈利测算 → 口语化结论 → 跨方案对比的完整决策链路，把复杂的选址过程变成一次轻松的对话。

1.3 为什么选择 AI 智能体

传统选址软件是"报表工具"：用户要先学会查数据、再自己读表下结论，门槛极高。而 AI 智能体把整个专业流程封装为对话能力——它听得懂人话、会自动调用数据引擎、会把结论讲成人话。这正是"AI 技术 × 垂直场景"的价值所在：让专业决策普惠化。更重要的是，我们把 AI 的"判断"建立在真实数据引擎之上，而不是让模型凭空猜测——这一点在第 03 章的对照实验中会详细展开。

03创新性分析

3.1 选题视角：把"专业决策"交给普通创业者

市面上选址工具多为数据报表型（面向分析师）或中介内参型（面向地产从业者），普通创业者根本用不起来。浙里选址选择了最"素人"的用户——个体创业者，把复杂的选址决策压缩成一句对话，切入了一个长期被忽视的真实场景。这一选题兼具社会价值（普惠专业决策）与商业价值（千万级个体创业者刚需）。

3.2 AI 与场景的融合突破

对话即入口

LLM 承担自然语言意图解析，把"我想在杭州武林广场开家30平奶茶店，月租8000"自动拆解为结构化参数，零学习成本。

决策即智能体

LangGraph 状态图编排多阶段决策流，智能体自主调用高德/58/评分引擎/盈利测算，全程实时可见。

结论即人话

LLM 把引擎返回的复杂数据翻译成"该不该开、为什么、要多久回本"，并如实转达风险。

3.3 差异化优势（vs 现有方案）

维度传统工具浙里选址
使用门槛需懂数据/报表一句话自然语言

3.4 核心技术亮点

  • 评分模型升级：客群匹配度从"POI 计数"升级为 Huff 引力累计（距离衰减 λ=2），竞品压力同理，理论基础更扎实；
  • 真实数据校准：以杭州湖滨银泰 / 宁波天一广场等核心商圈实测数据校准评分基准，非凭空设定；
  • 候选商铺卡片化：58 同城真实在租房源卡片一键选择，把"选铺"从文本对话变成点选交互。

3.5 品类画像参数设计（评分引擎的技术输入）

评分引擎核心输入是"品类画像参数表"，使评分"一店一策、一类一准"：

品类四维权重（客群/竞争/交通/租金）参考半径竞品基准客单价设计依据
奶茶0.35 / 0.25 / 0.25 / 0.15500m8 家¥16冲动型消费，"路过的人对不对"
甜品0.35 / 0.20 / 0.25 / 0.20800m6 家¥30目的性消费，看重商圈氛围
早餐0.30 / 0.20 / 0.35 / 0.15300m5 家¥10高频刚需，抢通勤动线
便利店0.40 / 0.25 / 0.20 / 0.15500m4 家¥15人口密度驱动复购

权重遵循零售选址理论：早餐把"交通可达性"抬到 0.35（通勤路上顺手买），便利店把"客群匹配度"抬到 0.40（依赖常住基数）。新增品类只需补一张画像表。

3.6 Huff 引力评分的数学模型

客群匹配度不是"数有几个 POI"，而是按距离衰减累计引力（P ∝ Σ(1/(d+d₀))^λ，d₀=50m 最小等效距离，λ=2 衰减系数）：越近的客群 POI 权重越高，避免"三公里外有个大学"被误判为高客流；竞品压力同理，越近越密的竞品扣分越狠。理论依据：Huff 引力模型（1963）、Reilly 零售引力法则（1931）、中心地理论。

04对照实验：纯 LLM 打分 vs 本系统 Huff 模型打分

4.1 实验动机

一个常见疑问是：既然用了大模型，为什么不直接让大模型打分，而要费劲做规则引擎？我们的答案很明确：纯大模型凭"常识与印象"打分，极易高估热门商圈、低估冷门精准点位——因为它不掌握真实的距离、密度、竞品分布数据。本节用对照实验证明规则引擎的不可替代价值。

4.2 实验设计

选取两个真实场景，分别用纯 LLM 直接打分（只给大模型文字描述，不给 POI 数据）与本系统 Huff 模型（基于真实高德 POI 距离计算）评估同一店铺，对比结果。

4.3 案例一：热门商圈（杭州湖滨银泰附近 · 奶茶店）

维度纯 LLM 打分本系统 Huff 模型差异分析
客群匹配度95（"网红商圈，人肯定多"）88LLM 凭印象高估；Huff 按真实 POI 距离衰减计算
竞争压力70（"商圈竞争大但能接受"）52LLM严重低估；Huff 检测到 500m 内奶茶竞品引力远超基准
交通可达性85（"地铁直达"）90Huff 基于真实地铁站/公交站距离核验
总分≈86（倾向"强烈推荐"）≈68（倾向"谨慎推荐"）LLM 结论偏乐观，可能误导创业者

※ 该案例揭示：热门商圈往往竞品同样扎堆，纯 LLM 只看到"人多"，看不到"店也多"，容易给出过度乐观的建议。

4.4 案例二：精准冷门点位（宁波某社区转角 · 便利店）

维度纯 LLM 打分本系统 Huff 模型差异分析
客群匹配度55（"社区店，人不多吧"）82LLM低估；Huff 发现 500m 内密集住宅 + 写字楼双客群
竞争压力60（"社区竞争小"）75Huff 核验同品类竞品确实稀少，社区空缺点位
租金承受力70（"社区租金低"）85Huff 按真实租金占流水比测算，性价比突出
总分≈62（倾向"不建议/一般"）≈80（倾向"推荐"）LLM 因"印象冷门"错杀一个好点位

※ 该案例揭示：冷门但精准的点位（如高密度住宅转角）往往被大模型"常识"忽略，而基于真实数据的引擎能发现价值。

4.5 实验结论

纯大模型擅长"解释"，不擅长"计量"。它能很好地组织语言、解读结论，但依赖训练语料中的"印象"，缺乏对具体坐标、距离、密度的真实感知，容易高估热门商圈、低估冷门点位。

浙里选址的价值正在于此：让 LLM 负责"人话"（意图解析、结论解读），让规则引擎负责"算数"（Huff 引力、盈利测算）——AI 判断 + 真实数据，缺一不可。这也是"可解释决策"的根基：每个分数都能追溯到真实 POI 数据。

05敏感度测试：参数变动如何影响评分

5.1 测试目的

选址评分对输入参数（尤其租金、搜索半径）的敏感度，直接关系结论的可靠性。通过敏感度测试，我们验证：评分对参数变化平滑、单调、可解释，进一步强化"可解释决策"这一核心亮点。

5.2 测试一：租金变动对"租金承受力"与总分的影响

以某奶茶店案例（基准月租 ¥8,000，参考月流水 ¥38,000，租金占流水比 21%）为例，考察租金变化：

月租租金占流水比租金承受力分总分变化结论
¥4,000（-50%）10.5%95+9租金极低，承受力几乎满分
¥6,400（-20%）16.8%86+4健康区间，加分
¥8,000（基准）21%75—基准线，处于安全区间上沿
¥9,600（+20%）25.3%61-5逼近警戒线（30%），风险上升
¥12,000（+50%）31.6%42-11超过警戒线，明确警示

※ 租金承受力随租金单调下降，总分平滑联动——创业者可以直观看到"每涨一千租金，风险上升多少"。

5.3 测试二：搜索半径变动对客群引力与竞争压力的影响

以某社区便利店案例为例，考察半径 300m / 500m / 800m 三档：

半径客群引力分竞争压力分总分结论
300m788076近距客群充足，竞品少，社区属性强
500m（基准）827580基准配置，客群与竞品均衡
800m856274纳入更远竞品，竞争压力下降但客群稀释

※ 半径扩大，客群引力上升（纳入更多 POI）但竞争压力同时上升（纳入更多竞品）——两股力量对冲，总分先升后降，符合"商圈辐射有最优尺度"的常识，评分逻辑可解释。

5.4 敏感度测试结论

  • 单调可预期：租金上升 → 承受力下降；半径扩大 → 总分先升后降，变化平滑无跳变；
  • 可解释：每个变化都能追溯到具体的引力计算与占比阈值，不存在"黑盒突变"；
  • 可用于决策：创业者可自行试算"如果我租金谈到 7 千，评分会怎样"，把"谈价"变成有依据的博弈。

这一特性正是"可解释决策"的落地证明——用户不仅能得到分数，还能理解分数背后的逻辑，并能主动用它指导谈判与选择。

07降级策略：系统如何保持稳定、高效

7.1 为什么需要降级策略

真实世界的选址分析依赖多个外部服务（大模型、高德 API、58 同城）。任何一个服务不可用，都可能让"一次完整的选址"中断。为保证系统运行稳定、演示可靠、用户不白等，我们设计了完整的三级降级体系。

7.2 LLM 三级降级链

火山方舟·豆包（主）失败→ 小米 mimo（备）失败→ DeepSeek（再备）失败→ 规则解读（保底）
层级触发条件效果
主模型火山方舟正常完整 LLM 口语化解读
第一降级主 key 欠费/超时/限流自动切到小米 mimo，解读不中断
第二降级前两者均不可用切到 DeepSeek
保底降级全部 LLM 不可用规则解读（模板化结论+数据证据），分析流程仍完整输出，仅语言风格稍朴素

※ 三个模型共用同一把火山方舟 Key 可减少配置；保底规则解读确保"即使大模型全挂，评分结论照样出来"——演示与生产都不会因 LLM 中断而崩溃。

7.3 数据获取降级链

实时高德 API失败/无数据→ 本地 SQLite POI 库仍无→ 返回空集+明确提示
  • 评分时优先查本地库（0 次 API、响应快），本地无数据才调实时高德（省配额）；
  • 实时高德失败自动回落到本地库，冷门地址也有兜底数据；
  • 两级都无数据时，不静默失败，而是明确提示该区域数据不足，避免用户误判。

7.4 候选商铺降级链（58 同城）

Playwright 抓 58 同城真实房源反爬/失败→ 回落高德 POI 候选商铺→ 区域中心坐标候选

网页抓取受网站反爬限制（详见边界说明），我们为此设计了双保险：抓取失败自动改用高德 POI 候选；仍无精确地址则用区域中心坐标（只 geocode 一次）兜底，保证候选列表始终可用。

7.5 成本与性能优化

优化项设计
API 预算控制每次地址分析约 6 次高德调用（竞品1+配套5类）；每类只搜 1 个代表词×1 页
地理编码去重区域中心只 geocode 一次；候选精确坐标设预算上限（默认 8 次）
本地缓存评分优先本地 SQLite；周边查询带进程内缓存，重复地址秒回
幂等重试高德抓取限速（0.3s）+ 失败重试（指数退避），中断可续跑
结果缓存分析记录持久化本地，跨会话复用，重复请求零成本

7.6 稳定性结论

得益于三级 LLM 降级 + 数据双兜底 + 候选多路回落，系统在任意单一服务故障时都不会中断主流程。实测：即使完全断开大模型，评分、测算、对比、PDF 全链路仍可完整输出；即使高德配额耗尽，本地库仍能支撑演示。这保证了答辩与演示场景的绝对可靠。

本作品为 AI 应用：以大语言模型（LLM）作为核心能力层，与规则引擎协同工作。

AI 能力在作品中的具体作用

8.1 AI 与规则引擎的分工（关键设计）

环节由谁承担为什么这样分工
意图解析规则引擎 + LLM规则兜底（零成本零延迟），LLM 补充模糊表达理解
评分计算规则引擎（Huff 模型）基于真实数据、可解释、可复现（见对照实验）
盈利测算规则引擎确定性计算，绝不让模型"编数字"
结论解读LLM把数据讲成人话，语气自然、贴近用户
风险提醒LLM + 规则规则检测硬性风险，LLM 组织成提醒语言

8.2 LLM 工程化设计（技术细节）

设计项实现方式
分层 PromptSystem Prompt 按"角色设定 → 任务定义 → 输出约束 → 风险话术"四层组织，结构化指令保证结论风格稳定复现
结构化输出要求 LLM 输出 JSON（含结论/理由/风险字段），前端解析渲染，杜绝自由文本格式漂移
温度参数结论解读任务 temperature=0.7（保留自然语气）；意图提取任务 temperature=0（确定性优先）
超时与重试单次请求 30s 超时 + 3 次指数退避重试，仍失败自动降级下一个模型（见第 07 章）
上下文注入评分与盈利数据以紧凑结构化文本注入 Prompt，控制 Token 消耗与响应延迟
空返回兜底LLM 返回空或非法 JSON 时，使用模板化结论兜底，保证输出永不为空

这套工程化设计确保：同一评分数据，多次运行结论语义一致（可复现）、LLM 故障不中断主流程（可降级）、单次解读成本仅数分钱（可规模商用）。

一句话总结 AI 的核心作用：大模型负责让系统"听得懂人话、说得出人话"，规则引擎负责让结论"算得准、算得清"。二者结合，才构成一个真正可用的选址决策智能体——AI 的智慧 + 数据的真实。

09作品功能说明

9.1 智能对话选址（核心）

  • 一句话发起："我想在杭州武林广场开奶茶店，30平，月租8000"；
  • 执行过程实时展开：定位、抓取、评分、测算逐步可见，透明可信，可随时折叠；
  • LLM 口语化结论 + 风险提醒 + 局限声明。

9.2 候选商铺推荐

  • 未指定地址时，自动抓取 58 同城真实在租店铺，卡片化呈现（租金/面积/位置/在租标签）；
  • 点击卡片即对该铺启动完整分析，零打字门槛。

9.3 可解释评分引擎

  • 四维度 0-100 分：客群匹配 / 竞争压力 / 交通可达 / 租金承受（+面积适配）；
  • Huff 引力模型计算客群引力与竞品压力，按品类权重加权总分；
  • 四品类画像（奶茶/甜品/早餐/便利店），独立权重与基准，真实商圈数据校准。

9.4 盈利测算

  • 水电（电价×用量 + 水价×用量）、人工、物料、固定成本；
  • 月净利估算、回本周期、盈亏判断。

9.5 右侧工作台可视化

  • 指标卡 + 雷达图 + 得分明细表 + 周边地图热力 + 证据引用；
  • 深色/浅色主题自适应。

9.6 跨会话全方位对比

  • 历史分析持久化；卡片勾选 2-4 个 → 多列表格 + 多雷达图 + 柱状图对比。

9.7 会话管理与报告交付

  • 多会话历史、打开/删除/导出；模型切换；
  • 一键导出 PDF 分析报告（评分+数据+结论+风险）。

9.8 知识库与答疑

  • 内嵌"选址打分依据""商业理论知识"说明页；
  • 支持对评分逻辑、商圈理论的自由追问。

功能闭环：对话 → 数据 → 评分 → 测算 → 解读 → 对比 → 报告，一条龙覆盖"从想到定"的完整决策旅程。

对照评审标准，本作品的价值主张如下：

评审维度本作品的对应优势
