## 2. 五项自评（我的判断，非官方打分）

### （一）创新性 30 分 → 预估 22～24

**站得住的**：

- 「竞价租金」这个视角确实是差异化：市面工具输出一个分数或热度指数，址南针输出**一个可以拿去谈判的金额**（盈亏平衡月租 ¥19,650 ／ 回本达标上限 ¥16,900，差额 ¥5,350）。P7 的两栏对照把这件事讲清楚了。
- 「非补偿性一票否决」有理论出处（Simon 的满意化），而且**有真实反例撑着**：早期引擎给一个「月净利 −¥5,327」的铺位打出总分 80.9 并判「推荐」。这个反例是硬证据，比任何形容词都有力。
- P6 的竞品对照表做得实：四类选项逐项列「它能回答／它回答不了／用户得自己补上的」，没有贬低对手，只划边界。

**被扣分的**：官方这一项问的是「**AI 技术与应用场景的融合方式是否有突破**」。当前全部差异化都压在经济学建模与口径纪律上，AI 部分读起来是标准件组合（VLM ＋ RAG ＋ 多 provider ＋ 降级）。评委追问「AI 在里面的突破点是什么」，现在的文档给不出一个可以立住的回答。

### （二）技术实现 30 分 → 预估 26～28

**这是全篇最厚、最硬的一段**，而且硬度来自「抓过什么东西」而不是「用了什么技术」：

| 页码 | 硬证据 |
|---|---|
| P9 | 拒绝伪严谨（定义式加权和上去回归必然 R²≡1，改做维度分自洽性检验，竞争压力与捕获份额 +0.883）＋ 拒绝调参（图检索对照实验输了就退回，RRF 只用排名）＋ 两层验证 ＋ 32 条局限 |
| P11 | 显式建图而非 while 循环、真 function calling（33 个工具词汇表／18 个可执行注册）、复合意图拆分、路由误判固化成回归用例 |
| P12 | 组合式 prompt（13 条公共铁律 + 九份人格）、**每个专家独立工具白名单**（政策顾问拿不到评分工具）、校验程序比对九份配置 |
| P13 | 限流被静默吞成空结果 → 报告写成「高德未收录该品牌」→ 用户读到「这个商圈没有蜜雪冰城」；四条修法 + 六种状态分流 + 本地库交叉验证 |
| P13 | 单位口径错误让结论翻转：接口返回的是**单杯价**，被当成**每单金额**，系统性低估流水 1.4～1.7 倍；三重对照取自招股书 |
| P15 | 十个真问题清单，第 10 条（返回值对、消费方用错，断言照样全绿）的补法设计得很讲究——用「顺序」表达不变式 |
| P16 | 品牌标定自我纠错：发现同一因素被算两次，相关系数 +0.6719 → +0.1531，显著品牌 7 个收敛到 3 个 |

**被扣分的**：官方这一项第一句是「**技术路线是否合理**」，而文档里**没有技术路线总览**。加上要素 6 的缺失，评委在「技术实现」这一栏会同时遇到两个空档。

### （三）实用价值 20 分 → 预估 14～16

**站得住的**：

- 痛点有官方数据托底：1.27 亿户个体工商户、2025 新设 1619.4 万户、餐饮闭店率 42.17%、单体门店半年闭店约 50%、门店平均存活 15 个月、浙江 748.96 万户／户均就业 1.92 人／正常经营率 78.20%。数字全部带出处与时间。

**被扣分的**：

### （四）用户体验 10 分 → 预估 6～7（截图填上可到 8）

- 没有量化交互指标：首次出结论耗时、完成一次分析需要几步点击、离线可用率、九专家切换的往返次数。

### 逐项复评理由

**（一）创新性 23 → 24。** 真正加分的不是新内容，而是**表述方向被扳回来了**：官方这一项问的是"AI 技术与应用场景的融合方式"，改前 P11/P12 写着"引擎产数据，LLM 只组织语言"，评委读到的是"AI 是文字包装"；现在改成"金额类事实由工具独占"（纪律收窄），并正面列出 AI 扛的环节。**天花板仍被同一个事实压着**：这个作品的突破点在经济学建模（反解租金 + 一票否决），AI 依附其上。要顶到 26+，需要论证"离开 AI 就做不到"的那件事——目前最接近的是 P12「引擎只算一次，九位专家各切视角」，但缺一张"同一铺位九种视角"的对照样张来落地。

**（二）技术实现 27 → 28.5。** 增益几乎全部来自**补漏**：官方点名的"介绍使用的开发工具"原先是**零覆盖**（关键词计数为 0），现在 P9 有一张 7 行技术栈表，层与层的关系清楚（编排／入口／模型／数据／兜底／检索／报告），"技术路线是否合理"这一问终于有落点。内容硬度本来就是全篇最高（P13 限流静默吞空导致陈述错误事实、P15 十个真问题、P16 显著品牌 7→3 的自我纠错），这部分没动。**仍偏弱**：没有性能数据（响应时长分布、并发能力），"系统运行高效"只有"毫秒级"一个孤立点。

## 3. 三处硬缺口（补齐即可直接提分）

### 3.1 「介绍使用的开发工具」= 零覆盖

**证据**（对渲染后正文做关键词计数，大小写不敏感）：

| 关键词 | 命中 |
|---|---|
| `langgraph` | **1**（仅 P11 的英文小标签「LANGGRAPH · 14 节点」，不成句） |
| `chainlit` / `sqlite` / `playwright` / `python` / `langchain` / `fastapi` / `ollama` | 0 |
| `框架` / `技术栈` / `开发工具` / `部署` / `前端` / `后端` / `数据库` | 0 |

结论：文档从头到尾**没有一段介绍开发工具与技术栈**。这是官方原文点名的要素，属于「漏项」而不是「写得不好」。

**建议补法**：在 P11（Agent 架构）页顶或 P9/P10 之间插一段约 1/3 页的技术栈表，按层列：

| 层 | 工具／选型 | 为什么选它 |
|---|---|---|
| 编排 | LangGraph（显式建图，多个阶段节点） | 可解释、可单测、能定位问题节点 |
| 对话前端 | Chainlit（自研 sidebar／三栏工作台） | 对话式入口，二次开发成本可控 |
| 模型 | 多 provider 链（含国产模型），VLM 独立用于门头识别 | 现场不押单一供应商，全挂可降级 |
| 本地数据 | SQLite 预抓取库（4.4 万条浙江 POI，12.9 MB） | 断网可演示，毫秒级响应，零 API |
| 检索 | 中文 2-gram TF-IDF 余弦相似度，纯标准库 | 74 条语料规模下，零外部依赖即可满足 |
| 训练／标定 | 自建回归门禁（17 套件）＋ Playwright 实机探针（52+ 断言） | 挡回退，也挡「其实没生效」 |

（具体选型以代码为准，写文档时从 `requirements.txt` 与 `src/` 核对一遍，别凭记忆写。）

### 3.2 「重点突出 AI 功能在作品中的核心作用」= 论证方向反了

P14 列了四个 AI 能力（视觉理解／检索增强／租金谈判助手／降级策略），逐项可验证，这部分没问题。

问题出在 P12 的一句话：

> **核心原则：引擎产数据，LLM 只组织语言。**

这句话在项目内部是**工程纪律**（防 LLM 编造行情数字），写得没错。但放在参赛文档里，与官方「重点突出 AI 功能在作品中的**核心作用**」正好对着来——评委读到的是「AI 在这里只是文字包装」。

**建议改法**（保住纪律，换掉表述）：

- 把「LLM 只组织语言」的**适用范围收窄**：它约束的是**金额类事实**（行情数字必须来自工具返回值），不约束 AI 的全部职责。
- 正面列出 AI 承担的核心环节：**一句话意图解析出五项参数**（把填表变成说话，这是零门槛交互成立的前提）→ **分支判定**（三个互斥起点，靠顺序硬约束）→ **复合意图拆分与路由** → **九专家视角解读**（同一套引擎结论，九种专业表达）→ **VLM 门头识别**折算形象分 → **RAG 注入**（政策原文与知识条款）→ **降级编排**（LLM 全挂时规则兜底）。
- 一句话结论改成类似：**引擎负责算得对，AI 负责让人用得起来——从一句话进，到一句能拍板的话出。**

### 3.3 「完整的使用说明（操作流程、交互指南）」= 缺失

P19 现在是「四个交互亮点 + 六张截图位」，属于**亮点展示**。官方要的是**说明书**：用户拿这个产品，第一步做什么、第二步做什么、每个入口能问什么。

**建议补法**：把 P19 改成「操作流程五步 + 交互指南 + 截图」，五步大致是：

1. **一句话发起**：在产品输入框写一句人话（示例：「我想在杭州武林广场开奶茶店，30 平米，月租 8000，预算 20 万」）→ 系统自动解析品类／地点／面积／租金／预算五项参数，无需填表。
2. **（铺位未定时）挑候选**：系统切分支抓取真实在租店铺并卡片化，点卡片即启动完整分析。
3. **看结论**：右侧结论工作台给出评分卡／雷达图／热力图，以及**两个金额**（盈亏平衡月租、回本达标上限）与房东报价的差额。
4. **换视角追问**：输入框上方常驻九位专家，可直接问租金、问竞争、问加盟费；也可一句话提多个诉求（复合意图会被拆开分别回答）。
5. **带走结论**：一键导出 PDF；勾选 2～4 个历史分析生成多方案对比看板。

再加一小块**交互指南**：能问什么／不能问什么（数据取不到时会显式说明哪一类数据缺）、九专家怎么切、报告怎么导出、多方案怎么对比。
