## 三、⚠️ 核心发现：uplift 在重复计入品牌力（共线）

### 怎么发现的

v2 结果里 `个体/杂牌` 从 **1.0599 掉到 0.8370**（n=557，CI 排除 1.0）。
而「个体/杂牌」恰恰是 **own_S = 1.0** 的那一档。于是追问：uplift 到底是什么？

> uplift = DP_门店 ÷ 同商圈中位DP，而 **DP 里的品牌差异只来自 own_S**
> （P 的分子是 own_S，分母 Σ S_k 对所有门店相同）。

### 检验（零 API 可复现，`recalibrate_uplift_v2.py §1b`）

把**所有门店**的 own_S 强制为 1.0 重算一遍（"品牌盲"）：

| 品牌 | own_S | uplift（全） | uplift（品牌盲） | 结论 |
|---|---|---|---|---|
| 蜜雪冰城 | 2.5 | 1.1958 | **1.0024** | 99% 由 own_S 解释 |
| 霸王茶姬 | 2.0 | 1.0829 | **1.0000** | 100% |
| 个体/杂牌 | 1.0 | 0.8355 | **1.0112** | 107% |
| 沪上阿姨 | 1.8 | 1.0000 | 1.0000 | — |
| 古茗 | 2.2 | 1.0741 | 0.9897 | 114% |
| 瑞幸 | 2.2 | 1.2992 | 1.1736 | 42%（**唯一还剩较多位置成分的**） |

- **盲测偏离 1.0 的中位幅度仅 0.0468**
- **Spearman(own_S, uplift_total) = +0.6719**

### 结论

> **uplift 提供不了 own_S 之外的独立信息。** 而流水里 own_S 已通过捕获份额 P
> 计入过一次，再乘 uplift 就是**双算**——品牌越强、多算越多。

- 这不是 v2 引入的：**v1 的构造完全相同**，只是 n=4~13 让 uplift 都挤在 1.0
  附近（±6%）把结构掩盖了；v2 的大样本把它放大成可见量级。
- 量级：自创品牌 −16.3%、喜茶 +18.8%、蜜雪 +19.0%、瑞幸 +25%（撞 clamp）。
  → 品牌之间的流水差距被**放大 1.42 倍**（1.19 ÷ 0.837）。

### 5.4 下游连锁：案例 F（天一广场 ¥12,000 蜜雪）整条链路上移 ⚠️

uplift 是**直接乘在流水上**的（`daily = base × (dp/ref_dp) × area × city × brand_factor × 0.6`），
所以换表必然带动下游每个数。**归因已钉死**（零 API 探针：把 `brands.UPLIFT['蜜雪冰城']`
回灌 v1 的 1.1343，逐位复现旧值 22265 / 70 / "谨慎推荐"）：

| 量 | v1（uplift 1.1343） | **v6（1.1903）** |
|---|---|---|
| 月流水（evidence / profit） | ¥99,552 | **¥104,467**（+4.93% = 1.1903/1.1343 − 1）|
| 月净利 / 净利率 | ¥10,265 / 10.31% | **¥12,688 / 12.15%** |
| 回本周期 | 12.6 月 | **11.0 月** |
| 盈亏平衡月租 | ¥22,250 | **¥24,700** |
| 回本达标月租上限 | ¥19,450 | **¥21,900** |
| 免租月净利 | ¥22,265 | **¥24,688** |
| 地址评分 | 85.8 | **86.1** |
| 经营评分 | 70 | **76** |
| **最终结论** | 谨慎推荐 | **推荐** ← 翻档 |
| 口径区间：流水 / 净利 | ¥99,552~¥139,722 / ¥10,265~¥30,069 | **¥104,467~¥146,620 / ¥12,688~¥27,709** |
| 不稳定租金窗口 | ¥21,000~¥39,000 | **¥22,000~¥36,500** |
| 三档（乐观/中性/保守） | 25,482 / 10,265 / **−2,677** | 28,372 / 12,688 / **−6,653** |

**两个必须一起讲的非直觉点：**

1. **区间上端净利反而下降**（30,069 → 27,709）。不是笔误，是**产能台阶**：
   `营业额刚性` 端的日单量 409 → **429 单/天**，跨过 3 人产能档（人均 140 单/天，3×140=420）
   → 测算按 **4 人**计人工，台阶吃掉流水增量。这是 `scoring.py:521-523` 写明的**预期行为**
   （"低价品牌自动得到更高的单量与更多的人工成本，而不是白捡一份流水"）。
   ⇒ **区间宽度本身含一个产能台阶，不是纯经济量**；拿它当"不确定性有多大"的度量要打折扣。
2. **保守档亏损加深**（−2,677 → −6,653）：保守档是成本假设更差的一档，流水上移但成本台阶上移更多，
   所以"情景敏感"的判断不变、甚至更强。

**结论翻档"推荐"完全由 uplift 贡献**（这条直接关系到 §八 的第 1 项待裁决）：

| 假设 | 月流水 | 地址评分 | 经营评分 | 结论 |
|---|---|---|---|---|
| uplift = 1.0（只保留 own_S 通过 P 的那一次） | ¥87,765 | 85.0 | 74 | 谨慎推荐 |
| uplift = v6（1.1903） | ¥104,467 | 86.1 | 76 | 推荐 |

即 **uplift 在 `own_S` 之外又给流水加了 +19.03%**，而 §三 已证 uplift 与 own_S 共线
（盲测几乎全回到 1.0）。所以这张表的意思是：**若裁决为"换成品牌盲残差"，本案例会回到"谨慎推荐"**。

## 九、局限（必须与结论一同呈现）

- **L1 本地库覆盖不完整**：实测 in77 库内 19 家 vs 实时 49 家 = **39%**、天一 65%。
  uplift 是同商圈内**比值**，分子分母同源受同一缺口影响、比绝对水平稳健，
  但**仍不能读成"真实流水倍数"**。
- **L2 商圈口径已换**：人工大区 → 最近商圈 POI。v1/v2 的数值差是
  "样本量↑ + 分组变细"的**混杂**，不可单读成"v1 错了"。
- **L3 own_S 取自 `BRAND_S`**（分档参考值）→ uplift 是"在给定 S 档位下"的相对水平。
  瑞幸尤须限定：它混的竞品是**奶茶店**，uplift ≠ "瑞幸流水比奶茶中位高 25%"。
- **L4 双算**：见 §三。这是本次最重要的一条。
