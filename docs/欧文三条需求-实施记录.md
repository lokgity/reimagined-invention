### 关键设计：这张表的每一个字都是被抽取器逼出来的

它不是"给人看的报告"，是**给人填、给机器读的输入表**，喂给专家 `store_diagnosis_advisor`
（`requires: monthly_revenue / monthly_rent / category`）。所以十个字段的**标签必须命中**抽取器的触发词，
且有三条硬约束：

1. **表体零数字（一刀切）**。`extract_*` / `_parse_*` 都是 `.search` 首匹配，任何印在表上的数字
   都可能抢在用户填的数前面被采信 —— 最坏情况是用户没填的那一栏命中**示例值**，被当成真实流水算进诊断，
   正是项目纪律里最不能接受的"认错还不报错"。**不做例外、不走白名单**，因为例外的维护成本高于收益：
   markdown 有序列表的 `1.` / `2.` 都会以数字字符进表体，所以表内一律用无序列表。
2. **说明文字不能出现"抽取器认得的词"**。本轮实测被这三处咬到（肉眼完全正常，抽取器眼里是数据）：
   - 品类举例「奶茶、茶饮、饮料店算同一类」→ 空表被解出 `奶茶`
   - 城市清单「杭州、宁波、温州…」→ 空表被解出 `杭州`
   - 「没有加盟就写『自创品牌』」→ `extract_brand` 的**自创分支是全文 `any(in)` 短路**，
     连用户真填的 `蜜雪冰城` 都被它盖掉（位置更靠前也没用）
   改法：说成"不含触发词"的话（「写你这家店实际卖什么」/「直接写城市名」/「没有加盟这一栏留空」）。
3. **填写位宽度有硬上限**。抽取器给"标签→数字"留的空档是有限的：

   | 抽取器 | 空档 | 备注 |
   |---|---|---|
   | `extract_area` | `[^\d]{0,4}` | **最紧** |
   | `_parse_price` | `[^\d]{0,4}` | **最紧** |
   | `extract_rent` / `extract_monthly_revenue` | `[^\d]{0,6}` | |
   | `_parse_daily_orders` | `[^\d]{0,6}?` | |
   | `_parse_investment` | `[:：]?\s*` | `\s` **认得 U+3000**，宽窄无所谓 |
   | `_parse_staff` | `(\d+)\s*(?:人\|名…)` | 数字在前，无所谓 |

   ⇒「标签 + 冒号 + N 个全角空格」必须 **N ≤ 3**（填 4 个，用户把数字写在空白段**末尾**时
   `面积` / `每单金额` 会静默取不到）。**不许用下划线**：它会挡住 `_parse_investment` 的 `[:：]?\s*`。

### 两层验证（本项目纪律：静态挡回退、实机挡"其实没生效"）

- **静态**：`src/analysis/verify_report_form.py`，**100 条断言**，已进离线门禁 `run_regression.py`。
  §1 零数字 + 填写位类型；§2 十项两种落笔位置（顶格写 / 写在空白段末尾）；§3 两条喂入路径
  （上传 docx / 只粘第四章摘要）等价，且**按 `_extract_docx` 的真实顺序模拟**（先段落、后表格）；
  §4 空表必须解出全 `None`（逼出追问，而不是猜）；§5 验 HTML 交付面；§6 验填写样例（见 §④）。
- **实机**：`src/analysis/live_report_probe.py`，**不进**离线门禁（要 python-docx + 成品 docx，
  且要两个解释器接力：venv 抽文本落盘 → cp314 跑真实抽取器）。判据：
  **空表 → 十项全 None；填好 → 十项全中**。实测 `FAILED=0`。

### 局限声明

- 本表**不含成本明细的自动测算**（表上已写明）：用户不报人工/水电/物料，由专家按品类画像拆十一项。
  附录的成本自查表**只供人工对账，不参与自动测算**，表上也写明了。
- 空表/半填时专家会**追问**，不会用经验值冒充实测值；经验值代跑会在结论里注明。
- 门禁验的是"**能被抽取器读全**"，**不能**验"用户填的数是真的"。数据真实性依赖用户自报，
  与已开店诊断的既有口径一致（流水用户自报、模型不估）。

## ② 自由对话优先级提到最高

**行为契约**：开启自由对话后，**无视已选专家** —— 可以问天气、电视剧等任意问题，不再受"选了哪个专家"影响。

**坑**：旧实现只在 `classify_node` 短路，但 `free_chat_node` 里 `_sel = state.get('expert')`
仍会接管**人设 / kb 分区 / 工具白名单** —— 表面自由对话、实际还在用专家口径。

**改法**：`free_chat_node` 里 `_free = is_free_chat_mode()` 为真时强制 `_sel=None`，
改走"通用助手人设"（问什么答什么；**没有实时能力就先声明、不许编**；用户主动问选址才切专业口径；
数字纪律不变），并 emit 一条"已选专家不生效"的 think 记录。
⚠️ **只作用于自由对话**，业务节点（选址 / 诊断 / 租金谈判）不受影响。

**门禁**：`verify_experts.py` §6c —— 捕获真实 `system` / `tool_mode` / `kb_tags`，
对照「选了专家 + 自由对话开/关」两组；§6b 覆盖诊断输入口径。全量门禁 rc=0。

**顺带修掉的 latent bug**：`_parse_investment(strict=True)` 把「月流水 8.6 万」读成前期投入 86000
（第 2 条规则"带单位即投入"）。修法 `_mask_revenue_rent` 先把已被"月租/月流水"认领的片段挖成
等长空格（复用 `agent.py` 的三套正则），且**租金支刻意跳过"预算"**（否则"预算 12 万"被一起挖没）。
证据：月摊销正确 **4167** vs 被污染 **2389**。

### ⚠️ 更正：「旧名归零」当时的结论是**错的**（2026-09-18 深夜查实）

改名后重启服务实机复验，`<title>` 里挂的还是旧名。追下去发现**漏了两处**，根因是两把尺子同时失灵：

| 漏掉的 | 为什么漏 | 影响 |
|---|---|---|
| `.chainlit/config.toml` 的 `[UI] name` | 改名脚本按**后缀白名单**扫（`.py/.js/.md/.html/.css/.json/.txt/.yaml`），`.toml` 不在名单里 | **应用标题**（`<title>`、`/project/settings` 的 `ui.name`）—— 唯一漏到用户眼前的一处 |

更隐蔽的是第二层：**`ripgrep` 默认跳过 `.gitignore` 里的路径，而 `.chainlit/` 正好在其中** ——
所以"全仓 grep 0 命中"从一开始就是**假绿**，两把尺子给出的是同一个错误答案。

**修法（不只改文件，是把这类漏洞封死）**：`verify_ui.py` 新增 **§9 产品名一致性**，进离线门禁：
- **不限后缀**扫全仓（自己 `rglob`，不信任何 ignore 规则），只排除产物/第三方目录与二进制/日志；
- 应用标题**单独钉死**（它就是漏掉的那一面，且必须重启服务才生效）；
- 针**拼出来**写（`'浙里' + '选址'`），否则本文件自己就是第一处"残留"，断言会自己把自己打倒

**实机复验**（静态挡回退，实机挡"其实没生效"）：改 `config.toml` 后**重启服务**，

### 三条设计约束

1. **能被抽取器读全**（不然这份样例没用）。十项逐项对齐，`_parse_investment(strict=True)` 尤其脆 ——
   它有命名口径表、裸"X万"不认，且须先把"月流水/S 万"掩码挖掉。
2. **算术自洽**：`日单量 300 × 每单金额 15 × 30 = 135000`（= 月流水）。样例是给人照抄的，
   自洽才经得起用户拿计算器验一遍。
3. **跑出来是一份正常经营的诊断**：实测 `diagnose_existing_store`
   → 月成本合计 116,239 / 月净利 18,761 / 净利率 **13.9%** / 安全边际率 **28.2%** /
   租金余量 18,760 / 品牌对标 **1.075**（达蜜雪冰城公开基准〔2024 年前 9 个月〕的 108%）。

   ⚠️ 这组数**不是**拿引擎反推的"标准答案"：先按真实奶茶店的账挑（蜜雪官方口径前期投入 37 万起，
   见 `agent/knowledge.py`），跑完引擎发现结论健康**才**留用。附录成本自查表也是照店主记账习惯填的
   （合计 99,300），与引擎拆解（101,239 − 租金）差约 2% —— **留这个差**：完全对上反而假，
   而且这张表的示范价值恰恰在于"专家拆的和你账上的对不上的时候，差在哪"。

### 门禁与实机

- **静态 `verify_report_form.py` §6**（新增，进离线门禁）：样例 md/html 与 `report_sample`
  构造结果**逐字节一致**（防"手工改了样例、数据源没跟着改"）；用真实抽取器解 md 与 html
  **各十项全中**；附录里印着的数字**不许抢走首匹配**；**填写位账要平** —— 空白表可见文本里
  28 个填写位（十项 + 摘要十项 + 附录八行）、样例里 **0 个**残留。
- **实机 `live_report_probe.py`（本轮扩到三组 + 最后一公里）**：空表 → 全 `None`；
  合成填表 → 全中；**交付样例 docx 本身 → 全中**；最后把抽出来的十个数直接喂
  `diagnose_existing_store`，验"这份 docx 真喂得动经营测算专家"。`FAILED=0`。

### 本轮踩到的两个坑（都是"只有实机/真数据才会露头"）

1. **`blank_span` 的"标签-空白同段"判定会误报**。摘要行填好之后，紧随其后的章节标题
   `第五章　口径说明与常见坑` 里的全角空格，其上文 12 字符内恰好有"日单量" ——
   按老判据会被算成"日单量还有一个空着"。修法：判据加**同一行**约束（`labeled_slots`）。
2. **HTML 模拟不能把每个 `<td>` 都换成换行**。真实 docx dump 用的是
   `' | '.join(cell.text)`（`live_report_probe.dump`），表格一行三格在抽取面上是**同一行**；
   按老写法"员工工资"与它的金额格分处两行 → 附录 8 个填写位凭空少 8 个（实测 28 → 20），
   判据假阳性。修法：`html_text` 改装成与 docx dump 同构。
