# 公网访问与内网穿透 —— 址南针

> 写这份文档的原因：作品现在跑在 `127.0.0.1:8502`，评委点不开。
> 但"让它能被公网访问"和"让它不被刷爆额度"是**两件事**，穿透只解决第一件。

---

## 0. 一句话结论

**内网穿透可以做，也值得做**——你的启动脚本已经是 `--host 0.0.0.0`，穿透只要把 8502 端口映射出去就行，代码不用改。

但它解决的是"**评委点得开**"，**不解决**"额度被刷光"（穿透只是换了个入口，key 照样在服务端被任何人触发）。
所以必须配套：**访问口令 + 每 IP 限流 + 全局日预算**（三道闸门已写好，见 §5），外加**演示视频兜底**（链接随时可能挂，视频不会）。

---

## 1. 什么是内网穿透

你家的电脑没有公网 IP。运营商给你的是一个"内网地址"（常见 `10.x` / `100.64.x`），
几十户人共用一个出口 IP。所以外面的人**没法主动连进来**——他连的是运营商那个共用出口，
出口不知道该把请求转给哪一户。

穿透的做法是**把方向反过来**：

```
你的电脑  ──主动连出去──>  中转服务器（有公网 IP）  <──访问──  评委
          ↑ 这条长连接一直保持不关，外部请求顺着它回传
```

关键点是：**不是外人连进来，是你自己先连出去**。
因为"往外连"永远被允许（你刷网页就是这个动作），所以不需要公网 IP、不需要在路由器上开端口映射。

一句话类比：你家没门牌号（无公网 IP），穿透就是你去快递站租了个信箱（中转服务器），
并保持一条电话线不断（长连接），别人寄到信箱的东西顺着电话线转给你。

**穿透 ≠ 组网**。Tailscale / ZeroTier 那类是"给设备之间拉一个虚拟局域网"，
需要访客**自己装客户端**——评委不会为了看你的作品装软件，所以这条路不适合参赛。

## 3. 三条路：怎么让评委点得开

| 方案 | 需要什么 | 稳定度 | 成本（量级，以官网为准） | 适合 |
|---|---|---|---|---|
| **A. 学校/实验室服务器**（有公网 IP 或有固定端口映射） | 一台服务器 + 你会部署 | ★★★★★ | ¥0 | **首选**，问指导老师/实验室 |
| **B. 商业穿透固定域名**（cpolar / 花生壳 / natapp 等） | 装个客户端，映射 8502 | ★★★★ | ¥30~100/月量级 | **次选**，最省事 |
| **C. 自建 frp** | 一台云服务器（轻量 ¥50~100/月）+ 会配 frp | ★★★★ | 服务器费 | 有服务器时最可控 |
| **D. Cloudflare Tunnel** | 一个域名 + cloudflared | ★★ | ¥0 | 免费，但**国内访问速度不稳**，只作备选 |
| **E. 免费随机域名** | 无 | ★ | ¥0 | ❌ **不要用**：域名每次重启就变，评委拿到的是死链 |

⚠️ **穿透服务的"免费版"通常给随机域名**——你今晚配好、明早重启一次，链接就变了。
参赛提交的是**死链 = 0 分**，比没有链接更糟（评委以为你作品跑不起来）。

## 4. 额度风险：穿透不解决，闸门才解决

你的担心是对的，而且比你想的更具体：

1. **key 明文在 `.env` 里**，日志文件里出现过 key 的话也一样泄露；
2. 服务**没有登录**，任何人打开就能用；
3. 一条选址分析 = 多次高德 POI 查询 + 多次 LLM 调用，一个爬虫几分钟就能刷掉日配额；
4. 你**自己调试**也在用同一个 key —— 被刷光意味着你当晚没法干活。

三道闸门（已实现，见 §5）分别挡什么：

| 闸门 | 挡的是 | 挡不住的是 |
|---|---|---|
| 访问口令 | 陌生人、搜索引擎爬虫、随手转发的路人 | 你把口令发出去之后的人（所以别用常用口令） |
| 每 IP 限流 | 单台机器狂刷 | **IP 可伪造**（X-Forwarded-For 客户端能塞假值） |
| 全局日预算 | **兜底**：上面全漏了，损失也封顶在这一层 | ——（这是最后一道，靠它保底） |

> 诚实说明：**这不是防盗门，是减速带。**
> 真要防专业攻击者，得在上游做（穿透服务端自带的限流 / Nginx / Chainlit 的 `CHAINLIT_AUTH_SECRET` 登录）。
> 对参赛场景，减速带够了——你要防的是"无聊的人和爬虫"，不是 APT。

## 5. 三道闸门：怎么开（已经写好并进了离线门禁）

代码位置：逻辑在 `src/ui/access_gate.py`，挂在 `src/ui/app_chainlit.py` 的
`on_chat_start`（入口口令）和 `on_message`（限流+预算）上。
回归套件：`src/analysis/verify_access_gate.py`（已注册进 `run_regression.py`）。

### 开关（`.env`，模板见 `.env.example`）

```ini
ACCESS_CODE=            # 留空=不启用；设了公网访客必须输口令
RATE_PER_MIN=12         # 每 IP 每分钟
RATE_PER_DAY=200        # 每 IP 每天
DAILY_BUDGET=400        # 全局每天总条数（超了当天拒答）
GATE_SKIP_LOCAL=1       # 内网来源豁免（本地开发零影响）
GATE_DEBUG=0            # 排障：打印每次请求拿到的 IP
```

### 默认值对本地**零影响**

- 没设 `ACCESS_CODE` → 口令关闭；
- `GATE_SKIP_LOCAL=1` → `127.*` / `192.168.*` / `10.*` / `172.16~31.*` 一律放行。

所以你在自己电脑上**感觉不到它存在**。它只对公网来客生效。

### 三条行为约定（写进代码里的，不是口头承诺）

- **预算超了是明确拒答**，不是"降级给你一份掺沙子的结果"（项目红线 1：宁少不掺沙）；
- **控制指令（`##` / `/` 开头的按钮动作）不计额度**，点按钮不扣；
- **计数落盘 `data/gate_usage.json`，按天滚动、进程重启不清零**——穿透服务半夜被重启一次不该白限。

## 6. 操作清单（约 30 分钟）

1. **配口令**：`.env` 里加 `ACCESS_CODE=<给评委的专用口令>`（不要用你常用的口令）。
2. **装穿透**：按服务商文档装客户端，把 **8502** 映射出去，**买/绑一个固定域名**。
3. **重启服务**（Chainlit 不热重载，改完必须重启才生效）。
4. **实机验证**（这一步不能省，否则是假绿）：
   - **关掉 WiFi，用手机流量**打开链接 —— 走 WiFi 你会命中内网豁免，测了个寂寞；
   - 应当看到要求输入口令；
   - 输对后连发 13 条消息，第 13 条应被"每分钟最多 12 条"拦下；
   - 开 `GATE_DEBUG=1` 看控制台打印的 IP：**必须是你手机的公网 IP**。
     ⚠️ 如果打印的是穿透服务器的 IP，说明它不传 `X-Forwarded-For`——
     所有评委会被算成同一个 IP，每 IP 限流会**误伤全部评委**。
     这种情况请把 `RATE_PER_MIN` / `RATE_PER_DAY` 调大（或设 0 关掉），**只留 `DAILY_BUDGET` 兜底**。
5. **录屏兜底**：把完整流程录成 4~5 分钟视频（脚本已在 `docs/演示视频脚本.md`）。
   **链接是加分项，视频是保命项**——链接挂了评委还有视频。

## 7. 我建议的组合（针对 iCAN 评委）

1. **首选问学校要服务器**（A），拿不到就买一个固定域名穿透（B，¥30~100/月）；
2. **演示用独立的 key**：高德另注册一个 key、LLM 另开一个子账号专供演示，
   和你开发用的**物理分开**——被刷了也不影响你干活；
3. **预算先设小**：`DAILY_BUDGET=150` 起（评委每人跑 3~5 条足够），跑一段时间再调；
4. **提交材料里同时给链接和视频**，并注明"如链接不可用请看演示视频"；
5. 别在这上面花超过半天——**它进不了前三，只是"评委能不能打开"的及格线**。

## 8. 已知局限（如实列出）

- `X-Forwarded-For` 可伪造 → 限流防"顺手刷"，防不住刻意伪造 IP 的人；
- 账本单机本地文件，多机部署各算各的；
- 你的电脑必须**常开不断网**：断电 / 断网 / 睡眠 = 链接当场失效（这是穿透方案相对于云部署的硬伤）；
- 家庭宽带的上传带宽一般较小，多人同时访问会卡；
- 预算超限是**拒答**，用户体验上会显得"突然不能用了"，所以 `DAILY_BUDGET` 不要设得太紧。
