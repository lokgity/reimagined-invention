# 仿真看板「入口」补齐说明（2026-09-21 · 方案 1）

> 改动时间：2026-09-21 02:15–02:35（自动化任务，DeepSeek V4.1 Flash 额度重置后接手）
> 关联决策：策 2026-09-20 21:21 选定「方案 1」

## 1. 要解决的问题

功能本身在 2026-09-20 已实机 **21/21 通过**，但**用户手够不着**，三处断层：

| # | 断层 | 证据 |
|---|---|---|
| ① | 左栏「快速操作」组没有看板按钮，只有 新建对话 / 导出分析 / 对比分析 | `public/sidebar.js:825-830`（改动前） |
| ② | 看板只是右栏分析工作台的一个 section，挂在 `if (d.map_b64)` 里 | `public/sidebar.js:1606-1614`（改动前） |
| ③ | `public/dashboard.json` 开新会话即被写成 `{"kind":"clear"}` ⇒ section 随之消失 | `app_chainlit.py::clear_dashboard()` |

**根因**：看板的生命周期被绑在「右栏当前页」上，而右栏是会话态的。

## 2. 改了什么

### 2.1 服务端 `src/ui/app_chainlit.py`

| 改动 | 说明 |
|---|---|
| 新增 `LAST_SIM_FILE = ROOT/'public'/'last_sim.json'` | 快照**独立于** `dashboard.json`，生命周期与右栏解耦 |
| 新增 `write_last_sim(sim, result, map_b64)` | 只在 `sim['ok']` 为真时落盘；`clear_dashboard()` **不碰**这个文件 |
| 快照字段 | `来源会话`（`cl.user_session.get('id')`）、`取证时间`（`%Y-%m-%d %H:%M:%S`）、`铺位`、`品类`、`lng`、`lat`、`半径m`、`map_b64`、`sim` |
| 新增 `build_analysis_dashboard_with_sim()` | 包装层。落盘是副作用，不污染纯函数 `build_analysis_dashboard()`（门禁要直接调它做对拍） |
| 两处调用点（原 1609 / 1943 行） | 由 `build_analysis_dashboard` 切到 `build_analysis_dashboard_with_sim` |

> 红线 1：快照只在仿真真的算出来时写。构造失败就**不写文件**，
> 不留一个"看起来能点开、其实是空的"入口。

### 2.2 前端 `public/sidebar.js`

| 改动 | 位置 | 说明 |
|---|---|---|
| 快速操作组新增按钮 | ops 组 | `data-cmd="simboard"`，文案「仿真看板」，图标复用 `ico('layers')` |
| 无快照时 `disabled` + `title` | 同上 | title 写明「现在还没有跑过分析……先跑一次选址分析」（红线 4：不静默，不许点了没反应） |
| `syncSimBoard(d)` | 新增 | 按钮可用性**只取决于有没有快照**，与右栏当前页无关 |
| 轮询 `/public/last_sim.json` | `load()` | 与 `dashboard.json` **分开拉**，所以不被 `kind=clear` 影响；404 属正常，静默 catch |
| `openPage('simboard')` 分支 | `openPage()` | 复用 `#zl-page-ov` 覆盖层（与知识库页 / 专家页同一个容器） |
| `simBoardHTML(d)` | 新增 | 顶部**来源表**（会话 / 取证时间 / 品类 / 经纬度 / 半径）+ 地图底图 + `simOverlay()` + `simMeta()` |
| `simBoardUnavailable(why)` | 新增 | 轮询还没到位时点按钮，也给一句人话，而不是什么都不发生 |
| 字体缩放层 | `wmStyle()` | 新增 3 条：**全部限定在 `#zl-page-ov` 下**，不去动右栏那份已被实机探针验过的 `.zr-legend` |

> ⚠️ 看板页**复用右栏同一套** `simOverlay()` / `simMeta()` / `simFigures()`，
> 不另写一份渲染 —— 两处渲染逻辑一旦分叉，就会出现"入口里看到的和工作台里不一样"。

### 2.3 门禁 `src/analysis/verify_road_sim.py`

新增 **§1b 入口可触达**（16 条静态断言），盯的是"用户手够得着"，不是"算得对"：

- 快照文件定义 / `write_last_sim()` 存在 / 只在 ok 时落盘
- 快照带 **来源会话 id + 取证时间 + 经纬度 + 半径**
- `clear_dashboard()` 函数体里**不出现** `last_sim`（注释已剥离，只看真代码）
- 两处调用已切到包装函数，且包装函数仍调纯函数
- 前端有 `data-cmd="simboard"`、无快照 disabled、有 title 说明、有兜底提示
- 复用同套渲染、独立轮询、`openPage` 分支、新元素进了缩放层

> 教训（写进门禁注释）：**实机探针 21/21 通过 ≠ 用户点得到。**
> 探针是在"刚跑完分析"的同一会话里验的，所以这条断层它一条都挡不住。

### 2.4 新增实机探针 `src/analysis/live_simboard_entry_probe.py`

验的是真链路：服务读到的 `sidebar.js` 含新按钮 → 真实 `build_sim` 结果能 JSON 往返 →
HTTP 能取到 `/public/last_sim.json` → **探针跑完删掉临时快照**（不留来路不明的入口）。

⚠️ 不跑它不会红门禁（与 `live_ui_probe.py` 同处境）—— 改了看板或入口，**必须同时 grep 这个探针**。
