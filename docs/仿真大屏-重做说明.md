## 2. 第一版错在哪

第一版做的是：**高德底图（`map_b64`）+ 叠一层轨迹 + 每个客群点一个小人走向本铺**。

问题不在"能不能跑"（实机 21/21 都过了），在**表达**：
- 底图里全是建筑、路名、地块色，小人贴在上面**看不清谁从哪来、去哪家店**
- 只有"去本铺"一个方向，**没有竞品分流**
- 小人一个流向一条，走完就重来，**看不出"人流量的大小"**
- 与右栏那块"周边热力图"长得几乎一样 ⇒ 策的判断是准确的：等于把热力图搬过来

## 3. 新版是什么

**不再用高德底图**，改成**自绘示意图**——只画关系，不画建筑：

| 画什么 | 从哪来（口径） |
|---|---|
| **马路骨架** | `data.road_path` 冻结的高德步行规划折线（走的人越多画得越粗） |
| **人流来源**（学校/写字楼/商场/小区） | `scoring.query_pois`（步行路网 ≤ 半径，**与 D/P 同一批点**） |
| **来源的客流权重** | `profile['target_pois'][].weight` —— **就是引擎算需求池 D 的那套权重**（奶茶：学校 .35 / 办公 .25 / 商圈 .20 / 社区 .20） |
| **竞品店铺** | `scoring.query_pois(同品类)` —— **与 Huff 分母同一批** |
| **小人的去向（分流）** | Huff 引力 `g_j = S_j/(d_j+d0)^λ`，λ=2.0 / d0=50m（与 `engine/scoring` 同常量） |

**"一直动态"怎么实现**：每个小人一条 `animateMotion` + `repeatCount="indefinite"`，
走到终点时 opacity 淡出（= 进店）→ 从来源重新出发。画面永远不会静止。

**"小人多少代表客流"怎么实现**：总小人 72 个，先按**类别权重**分到各类来源，
再在类别内按"到本铺的引力"归一。所以客流权重大的来源，走出来的小人就是多。

⚠️ **口径边界（必须一起讲）**：这里的"分流"是「**来源 → 各店**」的引力分配，
引擎的 `P` 是「**本铺 → 各竞品**」的捕获份额，**两者不是同一个量**。
大屏只做可视化，**不参与 D/P 计算、不改任何结论**——这条已写进画面脚注和门禁。

## 4. 迭代中实测修的四个坑（都是"不实机看就发现不了"的）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| ① | 节点**全挤在正中间**，小人糊成一团 | 直接用了整幅地图坐标（768px）；而 `map_geometry` 的 `width_frac=0.30` 是给"热力图"定的，节点实际只占一小块 | 视图框改用**内容包围盒** |
| ② | 牌子（标签）**跑出画布被裁掉** | 包围盒是在"牌子背离本铺偏移"**之前**算的 | 先排布牌子 → 再算包围盒 |
| ③ | 文字**溢出牌面**（"客流 25% · 348m"跑到绿牌外面） | SVG 里 `font-size` 的 px 是**用户单位**；牌子按跨度系数 K 缩了，字没缩 | 字号 = 基础 × 缩放层 × `--sbx-k`（JS 写在 `<svg>` 上） |
| ④ | 画面中间一坨、**四周大片空白** | 强制正方形 viewBox 被长边撑开（东西跨度常只有南北的一半） | 按内容**真实宽高比**，给最小边长兜底 |

> 「整体太小了，为什么是一个竖着的长方形呢？我要求把整个都做得大一些变成一个**横着的长方形**，可以把**整个子页面占满**，大一点，**少留点空白**，然后**小人的数量也做得多一些**，现在太少了，展示效果不直观」

| 要求 | 改法 |
|---|---|
| 横向长方形 | **先定横向视口 1560×975（1.6:1），再把地理坐标映射进去** |
| 占满子页面 | 大屏页改成 flex 列：顶部 chip 信息带 / HUD、SVG `flex:1` 吃掉剩余高度；`占子页 98%×78%` |
| 少留白 | 视口再按**容器真实宽高比**二次贴合（`sbxFit`）；横向剩余空间由环绕的牌子吃掉，另铺浅网格作底纹 |
| 小人更多 | `total_figures` 72 → **150**（实测出 57 个，路径按 share 分配） |
| 整体更大 | 尺度系数 K 改为按**视口**定（`VIEWH/700`），不再跟地理跨度走 |

**这一轮踩的坑（前两版都在"内容尺度"里打转）**：

1. 第一版：整幅图幅坐标 ⇒ 节点全挤在中间（`width_frac=0.30` 是给热力图定的）
2. 第二版：内容包围盒 + 强制横比 ⇒ **跨度小就整体缩小**，两侧还是空网格
3. 第三版（现版）：**放弃"内容尺度"，先定版面再映射** ⇒ 只有等比缩放，形状不失真；
   放大量上限 7×（再大就只是把两个本就很近的点拉得莫名其妙地远）
4. 牌子从"背离本铺推一点"改成**环绕在横向椭圆上**（按原始方位角排序后均匀铺开，
   保序 ⇒ 引线不交叉）——这是让横向真正铺满的关键

## 8. 第三轮：两个真 bug + 内容放大（2026-09-21 11:13 策实测）

> 「不要光放大地图啊，**马路也要放大**，**各个店铺之间的距离也要等比例放大**，而且**有些店铺怎么没有道路可以通过去**、小人也没走过去，然后**本店铺的人的到铺率怎么在百分之一百以上**？是不是你搞错了」

### ⚠️ bug ①「到铺率 >100%」—— 是算错，不是显示问题

HUD 原来写的是 `Σ share`，而 **share 是每个来源「内部」归一化的**（每个来源 Σshare = 1）。
4 个来源各 30%，一加就是 **120%** —— 分母口径根本对不上。

**正确口径**：`到本铺比例 = Σ(来源客流权重 × 该来源到本铺份额) / Σ(来源客流权重)`
（用小人分配的那套 `fig_by_src` 当权重），且**必须在裁剪之前算** ——
裁剪只决定画哪些线，不能影响统计数字。

实测修正后：武林广场 **51%**（此前显示 120%）。

### ⚠️ bug ②「有些店铺没有路」—— 裁剪只裁不补

裁剪规则是"每个来源只留 top3"，于是**某家竞品可能在所有来源里都排不上**，
画面上就孤零零挂着一个牌子、一条路都没有。

**修**：裁剪后**逐店铺兜底** —— 谁一条都没留下，就把它权重最大的那条补回来。

### 放大（马路 + 店铺间距一起放大，不是只放外框）

策的原话点得很准：上一版**牌子环绕撑满了版面，但路和店还挤在中间**（内容和牌子脱节）。

| 项 | 前 | 后 |
|---|---|---|
| 内容映射到视口的比例 | 58% | **72%**（实测放大系数 S 2.3 → 2.9，店铺间距 **+25%**） |
| 马路基准线宽 | 7 / 10.5 / 15 | **10 / 16 / 22** |
| 主客流高亮线 | 4K | **5.6K** |
| 小人尺寸 | 6.4K / 15.5K | **8K / 19.4K** |
| 环绕椭圆半径 | 0.375 视口 | **0.425 横 / 0.44 纵**（必须在内容之外，否则牌子压住店） |

### 9.1 卡片页（与对比分析同源）

原来大屏只能看"最近一次"（`last_sim.json`）。根因是**拿不到 analysis_id**：
快照在 UI 层生成，而 id 只有 `analysis_store` 知道 —— 且它**把 `add_analysis` 的返回值丢掉了**。

**修**：`add_analysis` 把 `entry['id']` **回写进 `result`**（零成本、零新依赖，result 是同一个对象），
UI 层据此把快照存到 `public/sim_boards/<id>.json`。

列表复用 `list_analyses()`（**与"对比分析"同一份数据**，两处顺序一致），
经 `sidebar.json` 的 `sim_list` 送到前端（⚠️ 键名不能用 `analyses` —— 那个已被"分析数(int)"占用）。

交互：点左栏「仿真大屏」→ **总是先给卡片列表** → 点某张卡 → fetch 那次的快照 → 渲染，
右上角有「← 换个分析」返回。没有快照的旧分析，卡片置灰并标「无大屏快照」。

⚠️ **踩的坑**：卡片点击处理一开始写在 `if (cmdBtn)` **里面**，而卡片不是 `[data-cmd]`
⇒ 永远不命中，点卡片毫无反应、连请求都不发。已挪到外面，并加了**顺序断言**守住。
