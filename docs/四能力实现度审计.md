## 一、VLM 门头照分析（`vision.py`）

### 1.1 实现了什么

| 项 | 内容 |
|---|---|
| 模型 | 火山方舟豆包视觉（`doubao-seed-2-1-pro` 支持图像输入），`thinking=disabled` + `max_tokens=800` |
| 输出 | 9 个结构化字段：是否门头实景 / 招牌文字 / 识别品牌 / 装修档次 / 门头可见度 / 卫生观感 / 观察描述 / 经营建议 / 评分修正 |
| 防幻觉 | 系统提示明令"只基于图片中真实可见的内容"；"不是门头实景 → 评分修正填 0"；`_clamp` 把评分修正锁死在 ±5 |
| 降级 | `LLM_ARK_MODEL` → `LLM_ARK_MODEL_FALLBACK` 双模型重试 |

### 1.2 两个入口

1. **用户直接上传**（`app_chainlit.process_storefront_image`）：识别到连锁品牌且会话未指定品牌时，**回写 `state['brand']`**，后续分析计入品牌引力 S。
2. **自动看铺**（`agent_graph` 选点后）：候选自带 58 实拍图 → 自动调 VLM，用户没上传也能看图打分。

### 1.3 并入评分的克制设计（`scoring.apply_storefront`）

- 形象分 = 0.5×装修档次 + 0.3×门头可见度 + 0.2×卫生观感，1-5 映射到 0~100
- **权重固定 10%**，其余四维按原比例缩放到 90%，重算总分与结论
- **明确不动经营测算**（流水/成本/回本）——照片只影响"形象"软指标
- **不绕过盈利一票否决**：结论沿用同一套判定（含 veto），注释写明"否则上传一张门头照抬高总分就能把'账算不过来'洗回'推荐'"
- 重复上传时先剔除旧维度再重加，避免权重膨胀

### 1.4 实测证据（`src/analysis/test_vision_storefront.py`，本次实跑）

真实 58 在租商铺实拍图，两张均 **PASS**：

| 图片 | 招牌识别 | 装修/门头/卫生 | 形象分 | 总分变化 |
|---|---|---|---|---|
| `storefront_58_0.jpg` | 御牛町 MIUSHIMACHI | 4 / 4 / 5 | 80.0 | 66.0 → 67.2 |
| `storefront_58_1.jpg` | 智能全自动 晓宝洗车 No.06 | 2 / 4 / 3 | 45.0 | 66.0 → 63.7 |

第二张图 VLM 还自主给了正确判断："若转做奶茶需拆除原有洗车相关标识，重新设计符合奶茶品类的醒目门头"——**跨业态迁移建议**是有价值的，不是套话。

### 1.5 缺口

1. ~~**UI 独立上传路径无总超时**~~ → **✅ 已修（2026-09-15）**：两条路径统一引用
   `vision.VLM_PER_MODEL_TIMEOUT=60` / `VLM_TOTAL_BUDGET=75`，UI 路径补上
   `asyncio.wait_for` 包裹与超时分支（超时只这一张照片失败，不影响评分与结论）。
   不变式 `2×单模型超时 > 总预算` 由 `verify_degrade_fallback.py` T9 锁定。
2. **无负样本回归**：只测了 2 张真门头图，系统提示里"logo/宣传图 → 是否门头实景=false
   不给假分"这条分支**仍无测试覆盖**（触发需真实 VLM 调用，离线测不了结构化契约之外的语义）。
3. 只采信"门头"一项视觉信号；店内环境、周边竞品视觉密度未做。

## 二、RAG 选址知识库（`knowledge.py`）

### 2.1 实现了什么

| 项 | 内容 |
|---|---|
| 语料 | **24 条**，6 大类：选址方法论 / 品类画像 / 成本政策 / 加盟政策 / 谈判签约 / 数据模型边界 |
| 检索 | 中文 **2-gram TF-IDF 余弦相似度**，纯 Python 标准库，零外部依赖，`min_score=0.05` |
| 注入点 | **4 个节点**：`interpret`（解读）/ `free_chat`（自由对话）/ `negotiate`（谈判）/ `competitor`（竞品） |
| 设计说明 | docstring 明确写了"为什么不用向量库"（语料小、离线稳定、演示不依赖网络），并给出迁移路径（千条级 → `doubao-embedding` + 向量库） |

### 2.2 实测证据（本次审计补跑的标注集）

> ⚠️ 方法学声明：这个 24 题标注集是**本次审计临时构造**的，题目措辞与知识条目标题接近，
> 因此结果**偏乐观**，不等于真实用户问法的命中率。它只能证明"语料-检索链路可用且不注噪声"。

- `recall@1 = 24/24 = 100%`
- `recall@3 = 24/24 = 100%`
- 无关查询（"今天天气怎么样""帮我写一首诗"、空串）→ **返回 0 条**，不往 prompt 里塞噪声

覆盖到的问法示例：跨品类选址（奶茶/甜品/早餐/便利店）、租金谈判、租约条款、转让费、加盟费（蜜雪/古茗/喜茶）、快招识别、外卖抽成、人工/水电/电价、Huff 原理、模型局限、品牌引力系数、λ 稳健性、蹲点方法、阴阳街。

### 2.3 缺口

1. ~~**无专属回归测试**~~ → **✅ 已修（2026-09-15）**：固化为
   `src/analysis/verify_knowledge_rag.py`（24 条标注 + 4 条题外话 + 规模哨兵 + 阈值哨兵）。
   纳入离线门禁组。
2. ~~**docstring 与实际不符**~~ → **✅ 已修**：文件头"30+ 条 / 30-60 条"改为"24 条 / 20-60 条"。
3. TF-IDF 是**字面匹配**，无同义/语义泛化；更口语的变体未做穷举压力测试。

#### ⚠️ 由该回归**新发现并修掉**的缺陷：`min_score` 阈值过松（2026-09-15）

把标注集固化成测试后，第一次跑就抓到 2 条 FAIL —— 原阈值 `min_score=0.05` 把
**题外话放进了知识注入**：

| 题外话查询 | 原行为（0.05） | 命中的知识条目 | 相似度 |
|---|---|---|---|
| 「今天宁波天气怎么样」 | ❌ 命中 | 样本稳健性 | 0.0968 |
| 「推荐一部好看的电影」 | ❌ 命中 | 商铺水电成本量级 | 0.0502 |

后果：用户在 `free_chat` 里闲聊天气，也会被注入一段"λ 稳健性"知识进 prompt，
**污染回答**。这正是"零测试 → 无声退化"的典型。

**标定过程**（不靠手感，靠实测分布）：24 条标注查询的真实命中最低 **0.1171**
（「奶茶店开在学校旁边怎么样」→「奶茶店选址要点」），4 条题外话最高 **0.0968**
→ 可分离间隙 `(0.0968, 0.1171)`，取中点量级 **0.11**。

修法：`_Index.search` 默认 `min_score` 0.05 → **0.11**，并把两侧分布与间隙写进注释；
测试里加**阈值哨兵**（`inspect.signature` 断言默认值 == 0.11），
今后改语料/改分词必须重跑该脚本重新标定，而不是悄悄把噪声放回来。

## 三、租金谈判助手（`negotiation.py` + `rental58.py`）

### 3.1 架构与分工

**引擎产数据证据，LLM 只组织话术，prompt 严禁编造行情数字**——与本项目"引擎产数、LLM 产文"总原则一致。

三条独立的线：

| 线 | 来源 | 定位 |
|---|---|---|
| 行情参考带 | 58 同城同区在租挂牌 P25~P75 元/㎡/月 + 完整样本标题 | **背景**（口径粗，不可当目标价） |
| 承受力上限 | `scoring.solve_rent_limits` 反解（盈亏平衡月租 / 回本达标月租上限） | **天花板**（唯一可当硬约束的数） |
| 结构化筹码 | 规则引擎产出 | LLM 组织成话术 |

### 3.2 关键修正（2026-09-14，语义严谨性很高）

1. **行情降级为参考带，不再产"建议目标价"**。原因写得很清楚：`area_filter` 只到行政区、不分楼层业态，实测宁波海曙最低 5 个样本是"社区底商兼仓库 / 大学食堂档口 / 可办公可娱乐场地 / 夜宵街招商 / 宿舍楼边档口急转"——**P25 是拿食堂档口算出来的**。旧版据此反推过"建议目标价 1239 元/月"，而用户自报单价是它的 5.6 倍。
2. **天花板 ≠ 开价**：明令 LLM 不许写"你可以先出 X 元"，筹码用**差额锚**（房东要 20 万、你最多付 6 万，缺口 14 万必须他降）。
3. **强制转达可比性声明**：写在筹码里并标注"必须原样转达用户，不许省略"。
4. **非同类业态"只披露不剔除"**：`NON_RETAIL_HINTS` 命中词进样本字段，但**不静默丢样本**——理由写在注释里："静默丢样本比留着混杂样本更危险（用户看不到自己少了什么）"。
5. **比价倍数差不读成"贵了 N 倍"**，而是判为"更可能说明两者不是同类铺子"。

### 3.3 测试覆盖（`test_veto.py` 案例 D / F）

已断言：
- 天花板只来自承受力上限、且不高于盈亏平衡线
- 筹码**没有**把天花板当开价报数字（正则扫"先出\s*[\d,]+"）
- 筹码明确"天花板不是'先出这个价'"
- 报价超天花板时给出**差额锚**（"谈判真正的锚是差额"）
- 无承受力数据时不给天花板（诚实退回）
- 强制转达可比性声明、披露样本标题

### 3.4 缺口（需知情）

1. **58 参考带不可复现**：列表每次返回 15~30 条不等，绝对价位落不到个位数——已如实声明，但意味着同一输入两次跑可能给出不同参考带。
2. `area_filter` 粒度只到**行政区，不到商圈**（已声明）。
3. **LLM 话术质量无自动化断言**：测试只覆盖到"数据包正确"，"LLM 有没有真的不编数字""有没有原样转达可比性声明"**没有机器校验**，靠 prompt 自律。
4. 挂牌价 ≠ 成交价（无成交数据，结构性局限）。

## 四、降级策略

### 4.1 四层降级

#### ① LLM 层（`agent/llm.py`）

降级链：**已选模型 → 豆包pro → 豆包turbo → mimo → DeepSeek → 规则解读兜底**（`agent.rule_based_interpret`）

| 机制 | 状态 |
|---|---|
| 总超时预算 `DEFAULT_TOTAL_BUDGET = 180s` | ✅ 防串行 5×120s = 10 分钟空转 |
| 按剩余预算动态裁剪单次 timeout | ✅ `min(timeout, remain)` |
| 切换 provider 前回调写「执行过程」面板 | ✅ `set_retry_callback` → `agent_graph:2264` 写「LLM 降级重试」步骤 |
| 会话级模型选择（contextvar 隔离） | ✅ 不跨会话串扰 |
| 规则解读兜底 | ✅ `rule_based_interpret` 输出完整结论（含租金临界点、三档区间、口径区间） |

**修过的 2 个真坑**（有文档）：
1. `DeepSeek-V4-Flash` 漏了 `thinking: disabled`（豆包 pro 有）→ 方舟默认深度思考 → 输出极长 → **界面卡 8 分钟**。
2. 无总预算 → 串行重试最坏 10 分钟，UI 零反馈。

#### ② 数据层

| 数据 | 降级路径 |
|---|---|
| POI（竞品/配套） | 本地预抓取库（0 API）→ 高德实时兜底（`realtime.py`，按类别省配额） |
| 候选商铺 | **58 → 高德 → 本地 4.4 万 POI 三级**，`used_fallback` 标记并写进 `src_hint` |
| 地理编码 | 高德 API → 本地 POI 库 → 知名区域坐标表（三级） |
| 竞品洞察 | 限流 / 日配额 / 真无同类**三者分开报**，不合并成"无数据"；`public_only` 状态 |
| 客单价 | 公开披露（招股书）→ 高德换算 → 品类画像 |
| 58 抓取 | 硬时限（>30s）→ 本地数据兜底；区域过滤无命中 → 放宽到全城 |

#### ③ 非关键路径"失败不阻断主流程"

VLM 门头分析、竞品口碑挖掘 —— 均 try/except 包裹，失败只写一条 step，主流程继续。

#### ④ UI 层

LLM 不可用 → 离线回复模板；模型未配置（mimo）→ 提示"回退默认链"。

### 4.2 缺口（需知情）

1. **180s 总预算仍偏长**：用户最坏要干等 3 分钟（比 10 分钟好，但对演示节奏仍偏长）。
2. **降级链串行**，无并行竞速（多 provider 同时发、取最快返回）。
3. **规则解读兜底在谈判/竞品节点是"降级为纯数据"**：不产话术，只输出结构化筹码——可用，但体验明显降档；这一点在 LLM 全挂时用户能感知到。
4. ~~**降级路径无自动化测试**~~ → **✅ 已修（2026-09-15）**：新增
   `src/analysis/verify_degrade_fallback.py`，9 组故障注入、零真实 API，见第七节。

### 7.1 降级故障注入覆盖（`verify_degrade_fallback.py`，零真实 API）

| 组 | 打断什么 | 断言什么 |
|---|---|---|

| T3 | 假时钟 + 各 provider 耗 100s | 超预算即跳过、**单次 timeout 被 remain 收紧**（120→80） |
| T4 | provider 切换 | 切换前回调必触发且带剩余预算；回调自身抛异常不带崩主流程 |
| T5 | —— | `rule_based_interpret` 兜底**自带全部关键结论**（三档/口径区间/租金临界点/局限）+ 确定性 |
| T6 | `agent_graph.call_llm` 全抛 | `interpret_node` 自动转规则解读、明写原因、写进「执行过程」面板 |
| T7 | 58 抓取失败 **+** LLM 全抛 | **承受力上限这条硬证据不能丢**、筹码逐条输出 |
| T8 | `agent_graph.call_llm` 全抛 | `free_chat_node` 走离线模板（有/无上下文两分支） |
| T9 | —— | VLM 时限不变式 `2×60 > 75`；两条路径均引用共享常量；无 KEY 必抛（不返回假数据） |

### 7.2 顺带修掉的两个真缺陷

1. **`min_score` 漏噪**（RAG）——见 §2.3。
2. **同步/异步降级回调文案不一致**——`call_llm_sync` 的回调只报"第 N 个"，
   不带已用时长与剩余预算，而异步版带。UI 的「执行过程」面板读这条文案，
   于是走同步路径时用户看不到"还要等多久"。已统一。

### 7.3 顺带加固的回归门禁

- `verify_flow_v2.py` / `verify_flow_graph.py`：**失败时原先不设退出码**（只打印），
  批量回归会把 FAILS 非空当成"通过"→ 门禁形同虚设。已补 `sys.exit(1 if FAILS else 0)`。
- 新增批量运行器：**离线门禁组 11 个套件**（必须 rc=0 且 FAILED=0）+ 网络依赖组 2 个（信息性）。
  注意必须**直跑脚本**：走 `_run.py` 包装层会把子进程 stdout 写进日志不转发，运行器看不到成败字样。

### 7.4 仍未闭合（诚实标注）

- **VLM 负样本**与**谈判话术转达**无机器断言：两者都需要真实 LLM 输出，
  离线无法确定性断言，只能靠 prompt 约束 + 人工抽查。
- **`客单价现实校验` 的口径混比**（见下）只做了**标注**，未改数值。

#### ⚠️ 未修但必须知情：客单价现实校验的"每单 vs 单杯"混比

`competitor_insight.analyze_competitors` 里：

```
assumed_price = profile['price']        # 每单金额（奶茶 ¥16）
ref_median    = 高德 biz_ext.cost 中位   # 实测≈单杯价（蜜雪 ¥7）
gap = (assumed - ref) / ref             # → +129%："假设偏乐观 129%"
```

两侧量纲不同（一杯 ≠ 一单），直接相除得出的百分比**不是精确偏差**。
这与 `docs/品牌级公开数据与客单价口径修正.md` 修掉的是**同一类单位错误**，
只是发生在"校验"而非"测算"上。

**本次只做了标注，未改数值**，原因：改数值会**翻转用户可见结论**——
若把参照组按 `UNIT_PER_ORDER=1.7` 折算成每单金额，全品类参照组的判断会从
"基本吻合"变成"偏保守"（16 vs 17×1.7≈29），而 `UNIT_PER_ORDER` 本身只是
两点估计、对高端品牌会高估。**这属于要用户拍板的方法学取舍，不擅自改。**
已做的三件事：
1. `说明` 文本追加口径提示（"一杯 ≠ 一单，倍数只表方向"）；
2. `客单价现实校验` 增加 `假设客单价口径` / `参照组口径` 两个字段；
3. `interpret_node` 与 `competitor_node` 的 prompt 要求 LLM **必须转达口径差异**，
   不许把百分比说成"流水被高估了这么多"。

同时修掉 `test_composite_intent.py` 一条**脆断言**：LLM 输出 `¥370,000`（带千分位），
原判据只认 `万`/`00,000`/`00000`，把格式差异误判成"模型没照做"。
