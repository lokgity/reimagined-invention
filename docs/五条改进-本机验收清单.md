## 2. 第 2 条：红队质证（模型审计师）

**验什么**：模型审计师多了一项能力 —— 除了质证"这套模型准不准"，还能质证"**这一次的结论**经不经得起推敲"。

### 2A 只验「角色在不在」（最快）

发：
```
你凭什么准啊
```
预期：切到 **模型审计师 纪明**，回答里应能看到他在讲**哪些参数标定过 / 哪些没标定**（比如价格-单量弹性是没标定的那一类）。

### 2B 验「结论质证」（要完整，也才算真验到）

1. 先跑出一个**带结论**的场景，例如：
   ```
   我想在宁波鄞州区万达广场附近开一家奶茶店
   ```
   等它出候选 → 从卡片里**选一个**（点卡片，或回复 `选1`）。
2. 等它给出**经营评分 / 净利润 / 租金天花板**这类结论。
3. **然后**再发：
   ```
   你凭什么准啊
   ```

### 预期（回答里应有固定的四步结构）

1. **列出关键假设**，至少 3 条
2. 每条假设**动摇时会往哪边偏**
3. 点名**最脆弱的那一条**
4. 给一个**你明天就能去核实的动作**（去问谁、去数什么）

### ⚠️ 最硬的一条判据：它**不许给出新的数字**

它只能引用**引擎已经算好的**东西（三档情景 / 口径区间 / 承受力上限）。

- ✅ 对：`按引擎给的三档情景…`
- ❌ **坏了**：它自己算了一个"如果租金降 10%，净利润会变成 ¥XX,XXX"这种**之前没出现过的数**

> 如果出现后者，**立刻告诉我** —— 那等于破了「引擎产数、LLM 产文」这条红线。

## 3. 第 3 条：地点解析（这条最直观）

**验什么**：说"某区某地标附近"，候选**真的落在那两个区**。

### 3A 主用例（这条改动修的就是它）

输入：
```
我想在宁波海曙区的火车站附近开一家奶茶店
```

| | 现象 |
|---|---|
| **改之前** | **0 个候选**（筛选词被错拼成「海曙区火车站」，58 一条都匹配不上） |
| **预期（改后）** | **出候选**（我今晚实测 56 条），且候选**都在海曙区** |

> 挂牌量每天在变，所以条数有出入正常。**判据是"出不出候选"，不是"几条"。**

**更硬的第二判据**：看左侧「执行过程」面板里 **`58同城·实时在租抓取`** 那一条，它的说明里应出现：
```
已按「海曙区」逐条校验区县归属，另有 N 条标题/位置都没写区县、无法证实归属未纳入（宁少不掺沙）
```

### 3B 副用例

```
宁波鄞州区万达广场附近开奶茶店，月租8000
```
预期：候选**都在鄞州区**（我实测 60 条）。

### 3C 冲突用例（验"地标和区县对不上会提醒"）

```
我想在杭州西湖区的滨江宝龙城附近开一家奶茶店
```
预期：回复**开头**出现提示，大意是：
```
⚠️ 您给的地名和区县对不上：说的是「西湖区」，按高德定位「…」实际落在「滨江区」。
```
（因为"滨江宝龙城"其实在滨江区。）

### 3D 没过滤的对照（确认没把老的场景搞坏）

```
我想在宁波开奶茶店
```
预期：正常出候选，**不报错**，条数跟以前差不多。

## 3.5 ★ 怎么核对「这些店真的在我说的地方附近」（2026-09-26 新增）

> 这一节是为回答策的原话：**「我怎么知道他给我的这些店铺确实在宁波海曙区的火车站附近」**。
> ⚠️ 上一版我给的判据是「看执行过程里那条校验字样」—— 那是**我自己的代码打印的**，
> 等于自己证明自己，**不算验证**。下面五条才是能独立核对的。

### ① 看卡片信息行的**距离**（最直接）

卡片上现在有：
```
距目标 1.4公里 [步行可达]
```
分档：`≤1公里`=步行可达 · `≤3公里`=3公里内 · `>3公里`=3公里外。

### ② 看卡片底部的**坐标**，拿去地图搜（最硬）

```
📍 29.86214, 121.53702
```
复制这两个数，粘到**高德地图 / 百度地图**的搜索框里回车 —— 落点在哪就是哪。
（格式是 `纬度, 经度`，与高德/百度一致。）

⚠️ 有 5 家卡片**不显示坐标和距离** —— 那些是「区域级·无门牌」，
平台只给了商圈名、**我们不知道它具体在哪**。**不显示 ≠ 在附近**，是真的不知道。

### ③ 点卡片上的「**58 原页 ↗**」

直接打开 58 的原始挂牌页，看平台自己写的地址、价格、面积。

### ④ 看卡片「地址」行**括号里的第一个词**（58 自己标的区）

```
海曙区启运路微电影产业园…（海曙-段塘启运86微电影产业园-宁波市海曙区空置中）
                     ↑↑↑↑ 括号里第一个词 = 58 平台自己标的区，不是我算的
```

### ⑤ 看回复**开头**的距离概况

现在会明说：
```
距「宁波海曙区火车站」的直线距离：最近 1.4公里、最远 8.4公里，
1 公里内 0 家（其中 10/15 家能精确定位，已按由近到远排序）。
⚠️ 58 是按区县给房源、没有按距离检索 —— 这个区此刻离得更近的挂牌就是没有。
```

### ⚠️ 必须知道的一件事：「附近」有数据源限制

**58 是按「区县」给房源的，它没有"按距离检索"这个能力。**
所以你说"火车站附近"，系统能保证的是「**海曙区的铺子**」，
但**不保证**「离火车站近」—— 实测最近的一家也在 **1.4 公里**外。

这不是 bug，是**数据源的天花板**。要让"附近"真正兑现，只有两条路：
- 加**半径筛选**（比如只留 3 公里内）—— 代价是候选会大幅减少，可能只剩几家
- 换一个**带经纬度检索**的数据源 —— 但要重做抓取层

**这两条我都没做，等你定。**
