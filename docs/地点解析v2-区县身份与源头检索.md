## 1. 改之前的三个 bug（全部实测）

### 1.1 `area_filter_of` 把地标当区域词 → 候选必然为 0

```
area_filter_of('宁波海曙区火车站', '宁波') = '海曙区火车站'   ← 修前
```

这个串在 58 的标题/loc 里**一条都匹配不到** ⇒ 候选数恒为 0。
根因是把两种词混为一谈：**地标是给 geocode 定位用的，不是区域词。**

修后：`'海曙区'`（认得出区县就截断到区县）。

⚠️ 既有行为逐字保留（门禁 `verify_place_first §?` 钉住）：
`area_filter_of('杭州滨江') == '滨江'`、`area_filter_of('滨江') == '滨江'`、
`area_filter_of('宁波') == ''`。

### 1.2 字符串包含过滤 → 既误杀也误收

`if area_filter and area_filter not in full`（`full = loc + title`）。实测宁波全市首页：

| 现象 | 实例 |
|---|---|
| **误杀** | `loc='轻纺城·塘西中路'` 真在**海曙区**，因没写"海曙"两字被丢 |
| **误收** | 全市页里 9 条江北 + 8 条鄞州 + 3 条镇海 + 3 条北仑 + 2 条奉化，标题恰好写了"海曙"就被当海曙留下 |

### 1.3 58 的 `loc` 到底长什么样（148 张卡片实测）

| 形态 | 占比 | 例子 |
|---|---|---|
| ① 结构化 `-{市}-{区}-` | 16/148 | `庄市·萌恒大厦-宁波市-镇海区-同心路888号…` |
| ② 简写 `{商圈}·{路名}` | 大部分 | `首南·天健巷127号`、`集士港·布政西路225号`、`余姚市区·新建北路181号` |
| ③ 一个区县名都没有 | **91/148** | `繁华商圈,带设备就可入场` |

**商圈名是关键线索**（首南→鄞州、集士港→海曙、长丰→鄞州、庄市→镇海），
修前的代码完全不认。

## 2. 源头检索：`?key={区县}`（本次最大增量）

### 2.1 先否掉的两条路

| 尝试 | 结果 |
|---|---|
| `m.58.com/nb/haishu/shangpu/` 等区县 URL | **全 0 张**（HTTP 200 但无可解析卡片） |
| PC 站 `nb.58.com/haishu/shangpu/` | 验证码 |

### 2.2 有效的路：城市首页 + 关键词参数

```
https://m.58.com/nb/shangpu/?key=海曙      →  89 张，全部海曙相关
```

| 来源 | 卡片 | 能判定属于海曙 | 跨区误收 |
|---|---|---|---|
| 全市首页 | 148 | **15** | 9 江北 + 8 鄞州 + 3 镇海 + 3 北仑 + 2 奉化 |
| `?key=海曙` | 89 | **58** | **0**（仅 1 张"西湖区"是别的城市噪声） |

⇒ **召回 3.9 倍，且零跨区误收。**

### 2.3 顺序也是设计的一部分

条目按 URL 顺序累积、攒够 `limit` 就停 ⇒ **关键词页必须排在移动端首页之前**，
让 60 条的预算优先给区县相关条目。实测分页产出：

```
  0  https://nb.58.com/shangpu/                          ← PC 首页，恒 0（验证码）
 54  https://m.58.com/nb/shangpu/?key=海曙区              ← 主力
  1  https://m.58.com/nb/shangpu/
  1  https://m.58.com/nb/shangpu/pn2/
```

（`?key=` 页已占一个 URL 槽；因 `max_parallel=4` 截断，尾部 `pn3` 被挤掉 ——
实测 `pn2/pn3` 在 `limit=60` 下产出为 0，无损失。）

## 3. 区县身份：三级判定

`rental58._item_district(item, city_cn)`，判不出返回 `''`（**不猜**）：

| 级 | 依据 | 说明 |
|---|---|---|
| ① | `loc` 的 `-{市}-{区}-` 结构段 | 平台自己给的，最权威 |
| ② | `loc` 首段商圈名 → 查**本地 POI 库** | **必须限定城市** |
| ③ | `loc` / `title` 里出现的区县名 | 复用 `agent_graph.extract_district` |

### 3.1 ② 必须限定城市（实测跨市串味）

| 商圈 | 不限城市 | 限定 `city='宁波市'` |
|---|---|---|
| `中河` | ❌ 衢州柯城区（"中河沿"） | 样本仅 2 条 → 判不出（见下） |
| `轻纺城` | ❌ 湖州长兴县 / 绍兴越城区 | ✅ 海曙区 |
| `首南`/`集士港`/`庄市`/`孔浦`/`东部新城` | — | ✅ 鄞州/海曙/镇海/江北/鄞州 |

### 3.2 ② 还要最小样本门槛（`_BIZ_MIN_N = 3`）

本地 POI 库是 **4.4 万条的抽样**，不是全量。样本过薄会给**假阳性**：

```
'中河'（宁波中河街道，实际在鄞州区）在库里只有 2 条，全是北仑区的
        "中河路(地铁站)"  ⇒ 判成北仑区（**错**）
判对的样本都厚：首南 7 / 集士港 7 / 长丰 7 / 庄市 8
```

⇒ `HAVING c >= 3`：**宁可判不出**（该条落进"无法判定"被丢），也不给一个错的区县。
代价：极少数真·小众商圈判不出（如 `轻纺城` 只有 1 条）。

### 3.3 过滤规则

- `area_filter` **本身是区县词**（`district_key` ∈ `DISTRICT_KEYS`）
  ⇒ 按**区县身份**比对；**判不出的一律不要**（宁少不掺沙）
- 不是区县词（`下沙`/`文三路` 这类商圈/路名）⇒ **退回原包含匹配**，既有行为逐字不变

### 3.4 "判不出"必须出声（不静默）

`meta['district_scope'] / ['district_dropped'] / ['district_unknown']` 三个字段，
并在「执行过程」里写清：`另有 N 条标题/位置都没写区县、无法证实归属**未纳入**`。

## 5. 地标 / 区县冲突检测

### 5.1 数据来源：`geocode_record()`

定位的**唯一实现**重构成 `geocode_record(addr)`（`geocode()` 降为薄包装），
把高德响应里本来就有的 `district` / `adcode` / `level` 留下来。

⚠️ **district/adcode 只来自高德（或本地修正表/商业质心路径），
绝不从地址串反推** —— 反推就等于"自己跟自己比对"，冲突检测会永远通过（**假绿**）。

缓存格式从 `[lng, lat]` 升级为完整记录，**读时兼容旧格式**（否则整份缓存失效、白烧配额）。

### 5.2 区级约束（`_city_hint`）

地址只写区县、不写市名时，高德会**串到外省同名区**：

```
'西湖区' 无 city 提示 → 南昌市西湖区 adcode 360103，(115.877, 28.657)   ← 跨省！
'西湖区' 带 city='杭州' → 杭州市西湖区 adcode 330106，(120.130, 30.259) ✓
```

⇒ 扫不到地级市时，用 `zj_districts` 区县表**反推地级市**再传 `city`。

### 5.3 校验逻辑

```
stated = extract_district(area)          # 用户口中的区县
actual = geocode_record(area)['district']  # 高德/修正表说这个点落在哪
不一致 ⇒ 出声提示，并以**实际所在区**继续检索
```

**只在两边都有值时才比**；高德没给区县就**跳过**（不猜）。

### 5.4 ⚠️ 一个必须记住的坑：修正表会"抢在高德之前"

`KNOWN_AREA_COORDS`（下沙/钱塘/未来科技城/滨江）方案零就先返回，
导致 `'杭州西湖区滨江宝龙城'` 拿不到高德区县 ⇒ 校验被**静默跳过**。
修法：该表的键本身是区名时（`滨江`→滨江区、`钱塘`→钱塘区）如实记下 ——
**这不是猜**，它就是这个坐标点所属的区。`下沙`/`未来科技城` 不是区名 → 返回 None。

实测：

| 输入 | 说 | 落 | 结果 |
|---|---|---|---|
| `杭州西湖区滨江宝龙城` | 西湖区 | 滨江区 | **冲突 → 提示** |
| `杭州钱塘区下沙` | 钱塘区 | 钱塘区 | 一致 |
| `宁波海曙区火车站` | 海曙区 | 海曙区 | 一致 |
| `宁波` / `下沙大学城` | — | — | 跳过校验 |

### 5.5 `enrich_district` 的边界

旧缓存只有坐标没有区县 ⇒ 校验会静默失效。可选参数 `enrich_district=True` 补一次，
**只补 district/adcode，坐标保持旧值**：

- ⚠️ **坐标必须冻结** —— 漂移会让候选距离/排序/占比全变，违反"同一输入同一结果"
- ⚠️ **判据是"有没有区县"，不是 `src == 'legacy'`** —— 实测修正表路径（`known`）
  写入的记录同样没有区县，只认 legacy 会让它们永远补不上
- ⚠️ **默认关闭** —— 这是额外的高德调用；批量场景（backtest 几百地址）默认开会成倍烧配额。
  只有 `search_rental_node`（每会话一个目标地址）显式打开

### 6.1 ⚠️ 踩到的一个门禁坑（记下来）

`verify_place_first §13` 的判据是**字面顺序**：

```python
rb.find("item['deal'] = _deal_type(full)") < rb.find('if area_filter')
```

我新加的 `?key=` URL 条件原本写作 `if area_filter:`，排在 deal 标记**之前** ⇒

**教训：往老函数里加分支时，先看门禁是不是靠"字面第一次出现"定位的。**

## 8. 已知局限（如实挂出）

1. **③标题 用的是区县名子串匹配**：标题写"滨江路"（在西湖区）会被判成滨江区。
   既有 `extract_district` 的固有精度，本次未加严（加严会动到门禁钉住的行为）。
2. **`_BIZ_MIN_N=3` 会误伤小众商圈**（`轻纺城` 只有 1 条 POI ⇒ 判不出）。
3. **`enrich_district` 的元数据只在 `search_rental_node` 打开** ——
   其他 `geocode` 调用方（backtest/专家工具）拿到的仍可能是无区县的记录。
4. **`geocode('文三路')` 会落到金华**（(119.173, 29.032)）——
   既有 bug（`_city_hint('文三路')` 返 None，高德自选），**本次未动**。
5. **实机验证未做** —— 需重启 Chainlit 后按 §4 的四个查询实测。
