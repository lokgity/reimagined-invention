## 三、问题 5：Graph RAG 召回对照实验

### 3.1 实验设计（脚本 `src/analysis/experiment_graph_rag.py`）

**为什么先做实验而不是先融合**：用户的原话是"**先试试看能不能真正提升召回**"。融合图检索会显著增加复杂度（实体抽取、图构建、融合权重），如果没有增益证据就上，等于用工程复杂度换一个说不清的好处。所以先把"图到底能不能提召回"变成一个可证伪的对照实验。

**图怎么建**：手工词典法。54 个规范实体，实际在 70 条语料中出现 46 个。

**四个检索器**：

| 检索器 | 定义 |
|---|---|
| `classic` | 现状：全语料 2-gram TF-IDF 余弦 |
| `graph` | 用查询实体在图上取邻接文档，按实体权重打分 |
| `hybrid (RRF)` | classic + graph 用 **RRF**（`Σ 1/(k+rank)`, k=60）融合 |
| `hybrid + 2hop` | 融合后再做一跳扩展 |

> **为什么用 RRF 而不是加权求和**：加权求和需要一个归一化口径 + 一个 α 权重，这两个都是"可调的自由度"。RRF 只用排名，**没有需要拍板的参数** → 避免"调参调出正增益"的质疑（这是本实验最重要的方法学选择）。

**三组查询集**：

- **A 组（71 条标注，反向哨兵）**：这组是**为 TF-IDF 设计**的，classic 本就该接近满分。图融合若在这里掉分，就是**纯伤害，没有借口**。
- **B 组（12 条难题）**：多跳 / 低词面重叠的口语问法（如"我怎么知道你的模型不是自己骗自己"）。
- **C 组（8 组多跳对）**：判据是**两条期望条目都进 top3** —— 这是图增强理论上**最该赢**的一组。

**公平性处理**：图只覆盖 52/70 条文档（**18 条是孤点**，如"选址金三角""转让费陷阱"）。为了**对"图这个思路"公平**，额外报了「**图上可覆盖子集**」视图——期望条目本身够不着的不算在图头上。**这是全实验唯一一次"调参"，而且是拒绝调参**：没有回头改词典把数字堆好看，而是补一个视图把事实摆出来。

### 3.2 结果

**全集：**

| 检索器 | A r@1 | A r@3 | B r@1 | B r@3 | C pair@3 |
|---|---|---|---|---|---|
| **classic** | **100.0%** | **100.0%** | 8.3% | 41.7% | 12.5% |
| graph | 73.2% | 88.7% | 8.3% | 41.7% | **0.0%** |
| hybrid (RRF) | 83.1% | 98.6% | 8.3% | 41.7% | 12.5% |
| hybrid + 2hop | 97.2% | 100.0% | 8.3% | **33.3%** | 12.5% |

**仅「图上可覆盖」子集（对图公平的那一套）：**

| 检索器 | A r@1 | A r@3 | B r@1 | B r@3 | C pair@3 |
|---|---|---|---|---|---|
| **classic** | **100.0%** | **100.0%** | 8.3% | 41.7% | **14.3%** |
| graph | 64.2% | 84.9% | 8.3% | 41.7% | **0.0%** |
| hybrid (RRF) | 77.4% | 98.1% | 8.3% | 41.7% | 14.3% |
| hybrid + 2hop | 96.2% | 100.0% | 8.3% | **33.3%** | 14.3% |

**自动结论（由数字推出，非预先立场）：**

```
graph：⚠️ 全集下把 A 组打坏（r@1 -26.8% / r@3 -11.3%）；正增益：无
hybrid (RRF)：⚠️ 全集下把 A 组打坏（r@1 -16.9% / r@3 -1.4%）；正增益：无
hybrid + 2hop：⚠️ 全集下把 A 组打坏（r@1 -2.8% / r@3 +0.0%）；正增益：无
```

### 3.3 为什么不提升——四条根因

1. **图覆盖不全**：只有 52/70 条文档可达，18 条孤点只能靠 classic 召回。图路线**先天丢掉 26% 的语料**。
2. **2-gram TF-IDF 已经吃下了表层词形**：本语料的查询-文档重叠主要靠共享字面词，词法检索本就命中；图能提供的是"语义上相关但字面不同"的邻接，而**这类需求在本语料里不占主导**。
3. **查询实体多映射到单条文档** → 图扩展拉进来的是**同实体的其他文档（噪声）**，不是期望条目。
4. **C 组的多跳需要"两条特定的文档被同时召回"**，而图扩展按"共享实体"撒网，**不保证两条目标同行**；实测 graph 在 C 组直接掉到 **0.0%**。

### 3.4 必须与结论一同呈现的三条边界

1. **B/C 两组是自建的，构造者 = 图设计者** ⇒ 本实验**不能证明泛化**，只能证明"在这套语料 + 这套图上，没看到增益"。
2. **语料仅 70 条**，量级一变结论可能翻转。图增强的经典收益场景（大语料、实体密度高、查询跨多文档）在 70 条上**根本没被触发**。
3. **不以"能不能调出正增益"为目标**：CAND/β/k 全部固定，没有对指标调参。唯一的"调参"是**拒绝调参**。

### 3.5 决策与后续

- **现在不融合。** 复杂度 > 收益，且收益为负。
- **触发重做实验的条件**：语料扩到**千级**（尤其补足"实体密度高"的条目），重建实体覆盖（把 18 条孤点纳入图），然后**用同一个脚本**重跑。若届时 hybrid 在可覆盖子集上稳定赢 classic，再谈工程化。
- **本次实验的可复用资产**：`experiment_graph_rag.py` 是一个**与结论解耦的评测脚手架**——换语料、换图、换融合公式都能直接复跑，不需要重写判据。
