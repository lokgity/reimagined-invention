## 1. 经济学原理（方案书"理论基础"章节，全清单）

> 这里是评委"你这分怎么来的"最先问的地方。**每条都给"用在哪 + 落点文件"**。

### 1.1 Huff 引力模型（Huff, 1963）—— 核心引擎

| 项       | 内容                                                                                  |
| ------- | ----------------------------------------------------------------------------------- |
| 公式      | 引力累计 `G = Σ(1/(d_i + d0))^λ`；捕获份额 `P = A/(A+B)`，`A = S/d0^λ`，`B = Σ S_k/(d_k+d0)^λ` |
| 参数      | `d0 = 50m`（最小等效距离，模拟到店距离、避免除零）；`λ = 2.0`（文献常用值）                                     |
| 与计数法的区别 | 传统方法"500m 内 3 家学校 = 3"；本模型"店门口 50m 的学校"与"500m 边缘的学校"权重**指数级不同**                     |
| 用在哪     | ① 客群匹配度（D：需求池引力累计）② 竞争压力（P：竞品引力比）③ 品牌分流强度（own_S 进分子）                                |
| 落点      | `src/engine/scoring.py`；`docs/品类画像参数表.md` §五                                        |
| 答辩话术    | "这不是我们自己拍的公式，是 Huff 1963 的零售引力模型在单店选址上的实例化。"                                        |

### 1.2 Reilly 零售引力法则（1931）

- 落点：`docs/品类画像参数表.md` §六"模型依据"

### 1.3 中心地理论（Christaller）—— 解释"为什么每个品类的半径不同"

| 品类  | 参考半径     | 经济学解释（**可直接抄进方案书**）                        |
| --- | -------- | ------------------------------------------ |
| 早餐  | **300m** | 最低门槛商品（高频、极低价、刚需）→ 服务半径最小，选址本质是"抢动线"       |
| 奶茶  | **500m** | 低门槛商品 + 高频次冲动消费 → 靠"路过的人对不对"，不靠"住在周围的人多不多" |
| 便利店 | **500m** | 高频低值 + 强复购 → 靠"人口基数 × 复购频次"                |
| 甜品  | **800m** | 较高门槛商品（目的性 + 场景性消费）→ 服务半径更大，更看重可达性         |

- 落点：`docs/品类画像参数表.md` 各品类 §5、§一~§四
- **答辩金句**："我们四个品类的半径不是拍脑袋，是**中心地理论的直接推论**——门槛越低，半径越小。"

### 1.4 商圈理论 / 市场饱和度

- **竞争饱和基准**（品类差异化设定）：奶茶 500m 内 ≥8 家、甜品 800m ≥6 家、早餐 300m ≥5 家、便利店 500m ≥4 家
- 依据：头部品牌同商圈加密密度 + 行业报告量级（如中国连锁经营协会便利店报告），**量级估计**
- 落点：`docs/品类画像参数表.md` 各品类 §4；`docs/架构文档.md` §6.1

### 1.5 竞价租金理论（bid-rent）—— **创新点 1 的理论根基**

| 项            | 内容                                                                   |
| ------------ | -------------------------------------------------------------------- |
| 主张           | 一块地值多少钱，**取决于它能产生的剩余（residual）**                                     |
| 本项目落地        | 不是问"租金贵不贵"，而是**从利润倒推"你最多能付多少"**                                      |
| 两个临界点        | ① **盈亏平衡月租**（净利恰为 0）② **回本达标月租上限**（3 年租约前 2 年收回投入）                   |
| 算法           | **二分法反解**，零 API、结果确定可复现                                              |
| 落点           | `src/engine/scoring.py::solve_rent_limits`；话术见 `docs/创新点与路演话术.md` §二 |
| **必须一起讲的差异** | "这不是给你一个价格建议，是给你一个**不可突破的天花板** + 一个**可谈判的目标价**"                      |

### 1.6 非补偿性决策 / 满意化（satisficing, Herbert Simon）—— **创新点 2 的理论根基**

| 项             | 内容                                                                                  |
| ------------- | ----------------------------------------------------------------------------------- |
| 痛点            | 市面工具都用**加权求和**，加权是**补偿性**的：一个维度极低能被别的高分补回来 → 出现"总分 80.9、判推荐、月净利却是负的"自相矛盾            |
| 方案            | 把"能不能赚钱"从加权里**抽出来**，做成**非补偿性硬约束**：月净利 ≤0 或回本 >24 月 → 强制改写为"位置好·账算不过来"，**经营评分封顶 59** |
| 理论出处          | 决策科学中"满意化"而非"效用最大化"（Herbert Simon）                                                  |
| 现实依据          | 选址是**不可逆沉没成本决策**，真实创业者决策规则本就是"**先过生死线，再比好坏**"                                       |
| **证据（这条最有力）** | **真实踩过坑逼出来的**：早期加权求和实测出现过"总分 80.9、月净利为负"却判推荐；改非补偿性后这类错误被**结构性**堵死                   |
| 落点            | `src/engine/scoring.py`；`src/analysis/test_veto.py`（47KB 专项套件）                      |
| 双轴输出          | 为避免自相矛盾，结论**双轴展示**：位置分结论（五维加权）∥ 综合结论（含一票否决）                                         |

### 1.7 盈亏平衡分析

- 变动成本率 `v = 物料 + 损耗 + 外卖占比×抽成率 + 场地附加 + 税负`
- 固定成本 `F = 租金 + 人工 + 水电 + 摊销 + 品牌费 + 杂费`
- `盈亏平衡月流水 = F/(1−v)`；`安全边际率 = (实际流水 − 平衡流水)/实际流水`
- **刻意不引外部经验阈值**（如"安全边际 ≥20%"），改用**自洽检验**：流水代回模型净利必须 ≈0
- **双算法互校**：自解 vs `solve_rent_limits` 独立二分，实测差 **¥13**（¥13,663 vs ¥13,650），已固化为断言
- 落点：`src/engine/store_diagnosis.py`；`docs/经营测算口径与已开店诊断.md` §3.3

### 1.8 价格弹性 / 需求-价格关系 —— **未被标定的自由度（诚实披露）**

| 项        | 内容                                                                    |
| -------- | --------------------------------------------------------------------- |
| 问题       | 引擎 `月流水 = 日单量 × 每单金额`，但换客单价时**日单量不跟着动** → 等价于假设**需求对价格完全无弹性（弹性 = 0）** |
| 现实       | 连锁茶饮恰恰相反：低价品牌靠高频走量（弹性 ∈ (−1, 0)）                                      |
| 后果       | 低价品牌流水被压低 → 结论偏悲观；高价品牌被抬高 → 偏乐观                                       |
| 处置（方案 A） | **模型不动**，把两个建模极端并列：**单量刚性（弹性 0）** ∥ **营业额刚性（弹性 −1）**                  |
| **关键增值** | 不只给区间，还**算出结论对弹性的敏感性**：两端结论相反时标 `结论不稳健` 并出 🚫 级警告                     |
| 落点       | `src/engine/scoring.py::elasticity_band`；`docs/口径区间-价格弹性未标定.md`       |

### 1.9 其他被用到的经济学概念（散落在实现里，可成段）

| 概念                          | 用在哪                                                                                                                                      |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **沉没成本 / 不可逆决策**            | 全篇立意：为什么要"前置为可逆的信息决策"                                                                                                                    |
| **一次性投入与回本周期**              | 回本 ≤24 月作为硬约束                                                                                                                            |
| **外卖平台抽成的性质是渠道费用、不是产品成本**   | 毛利率**不**含外卖抽成：`毛利率 = (流水−物料−损耗)/流水`（**产品口径 / COGS 口径**）；外卖抽成**单列**占流水比 `35%×22% = 7.7%`。理由：混进去会掩盖"外卖占比本身就是成本变量"这一**可行动杠杆**               |
| **变动成本 / 固定成本二分**           | 安全边际与临界点反解的基础                                                                                                                            |
| **非单调性（认知陷阱）**              | **月流水↑ 不等于净利↑**：`derive_staff` 按日单量**台阶跳**（人数 = ⌈日单量/人均日单量⌉），跳档会让净利回落。实测 ¥55,000 → −4,623；¥60,000 → **−7,918 ↓**。**"提高流水一定改善回本"这个直觉不成立** |
| **共线性 / 抑制效应（suppression）** | `corr(D, P) = −0.5111`（需求密集处竞品也密集）→ D 与 P **禁止同回归**，实测 β(P) 从 +82.17 翻到 −49.10                                                           |
| **统计功效（power）**             | 品牌溢价"不显著"的正确读法是"**测不出**"而非"无差异"——连蜜雪 n=13 功效也只有 0.53                                                                                     |
| **代理变量（proxy）的效力边界**        | 用"外卖月售"作经营代理被**证伪**：与 P 相关 **−0.229（p=0.037）**，方向与预期相反                                                                                   |
| **单位口径 / 量纲一致性**            | 把"单杯价"当"每单金额"→ 系统性低估 1.4~1.7 倍（详见 §5.6）                                                                                                  |

#### ⭐ GraphRAG 对照实验 —— **建议整节进方案书（负结果最显严谨）**

- **动机**：用户原话"**先试试看能不能真正提升召回**"。融合图检索会显著增加复杂度 → **先把"图能不能提召回"变成可证伪的对照实验**
- **实验设计**：54 个规范实体（实际出现 46 个）；四个检索器 `classic` / `graph` /  
  `hybrid (RRF, k=60)` / `hybrid + 2hop`；三组查询集 A（71 条标注，反向哨兵）/ B（12 条难题）/ C（8 组多跳对）
- **结果（全集）**：

| 检索器             | A r@1      | A r@3      | B r@1 | B r@3     | C pair@3 |
| --------------- | ---------- | ---------- | ----- | --------- | -------- |
| **classic（现状）** | **100.0%** | **100.0%** | 8.3%  | 41.7%     | 12.5%    |
| graph           | 73.2%      | 88.7%      | 8.3%  | 41.7%     | **0.0%** |
| hybrid (RRF)    | 83.1%      | 98.6%      | 8.3%  | 41.7%     | 12.5%    |
| hybrid + 2hop   | 97.2%      | 100.0%     | 8.3%  | **33.3%** | 12.5%    |

- **结论**：**图增强在任何一组、任何子集上都没有赢过 classic** → **暂不融合**
- **方法学亮点（这条比结论更值钱，务必写）**：
  1. **用 RRF 而非加权求和** —— 加权求和需要归一化口径 + α 权重两个"可调自由度"；**RRF 只用排名，没有需要拍板的参数** → 避免"调参调出正增益"的质疑。**这是全实验最重要的方法学选择**
  2. **拒绝调参**：图只覆盖 52/70 条（18 条孤点）→ 为对"图这个思路"公平，**额外报一个「图上可覆盖子集」视图**，而不是回头改词典把数字堆好看。**"这是全实验唯一一次'调参'，而且是拒绝调参"**
  3. **三条边界必须同呈现**：① B/C 两组是自建的、构造者=图设计者 ⇒ **不能证明泛化**；② 语料仅 70 条，量级一变结论可能翻转；③ 不以"能否调出正增益"为目标
  4. **可复用资产**：`experiment_graph_rag.py` 是**与结论解耦的评测脚手架**——换语料/换图/换融合公式都能直接复跑
  5. **重做条件**：语料扩到**千级** + 重建实体覆盖（纳入 18 条孤点）→ 用**同一个脚本**重跑

### 3.2 取数确定性 —— 从"不可复现"到"严格可复现"

> **这是一个完整的故事，建议成段写**。

**症状**：同一地址同一品牌，两次评分月流水**差 2.29 倍**，报告不可复现。

**追因（量化证据）**：

- 成功时 POI 条数**恒定**（in77 = 25/25、天一 = 25/25）；同品牌样本数**恒定**；人均中位**恒定**
- **连续无间隔调用：第 5 次起**返回 `CUQPS_HAS_EXCEEDED_THE_LIMIT`
- **间隔 2s 再调：全部恢复**
- ⇒ **非确定性 100% 来自高德 QPS 限流，不是数据源抖动**

**根因（三层叠加）**：

1. **限流被静默吞成"空结果"** —— `if data.get('status') != '1': return []`，限流和"这一带没有竞品"变成同一个值
2. **下游据此写出假结论** —— 明明是限流，却说"高德未收录"。用户会得&#x51FA;**"这个商圈没有蜜雪冰城"**&#x7684;相反结论。**"它不只是算错数，而是陈述了一个错误事实"**
3. **结果不落盘** —— 每次重打接口；且同一链路里两个函数用完全相同参数**各打一次**，把限流概率翻倍

**修法（四条，全部可写）**：

1. **抓取层带出失败原因**：`(pois, meta)`；按 infocode 分两类决定"重试有没有意义"
   - `RETRYABLE`（10021/10020/10004，QPS 超限）→ 退避重试 0.4s→0.9s→1.8s（总 <3.2s）
   - `QUOTA`（10003/10019，日配额耗尽）→ **不重试**，明确告知"今天取不到"（避免用户以为"高德没这个数据"）
2. **持久化冻结缓存** `data/competitor_cache.json`：缓存的是**原始 POI 快照**（不是某个品牌的价格）→ 同坐标**换品牌也复用**
   - TTL：**成功 30 天** / **失败 180s**（够让一次会话内数字不跳，又能在限流解除后自愈）
   - 原子写入（先 `.tmp` 再 `os.replace`）；上限 400 条
   - **副产物**：同一地址评分从 2 次 API 降为 1 次，重复分析降为 **0 次**
3. **口径按六种状态分流，互不混同**：`ok` / `public_only` / `fetch_failed` / `no_same_brand` / `self_brand` / `underpowered`
   - `fetch_failed` 必须声&#x660E;**"这不代表附近没有该品牌"**
4. **限流时用本地库交叉验证存在性**：本地库证明"该品牌 1km 内确实有 N 家门店，只是本次没取到价格"
   - **直接反驳"限流 = 附近没有这家店"这一误导**

**实测结果**：首次取数 1 次 API / 0.3s；**后续 5 次 0 API，17 项结果指纹只有 1 种**；端到端两次 `score_site` **完全相同**

- 落点：`docs/竞品取数确定性与限流修复.md`；`src/analysis/verify_price_ref_determinism.py`（**17 项全 PASS**）

### 3.4 品牌溢价标定（UPLIFT）—— 现行 v7 口径

> ⚠️ **绝对不要引用 v6 及更早的数值**。以下是 v7。

**现行定义（v7 = 品牌盲残差）**：

```
DP_blind = D × P(自己 own_S := 1.0，竞品 S 保持真实)
uplift   = 1 + w·(median(DP_blind ÷ 商圈中位DP_blind) − 1)
w = n/(n+5) 收缩；clamp 分层：TIER1 免 / TIER2·TIER3 仍 (0.80, 1.25)
```

**读法**：度量"**假设该店没有品牌力**，它还比同商圈中位店好多少"＝**位置/竞争微区位残差**。  
⇒ **uplift 现在只能读作「位置残差」，不是「品牌溢价」，更不能读成「流水倍数」。**

**为什么改（v6 → v7，消双算）**：

- v6 的 `DP = D × P(真实 own_S, 真实竞品 S)` → P 的分子是 own_S，而流水里 own_S 已通过 P 计入一次，  
  `brand_factor` **又乘一次** → **双算**
- 正交性检验：`Spearman(own_S, uplift_raw)` 从 **+0.6719 → +0.1531**

### 3.5 模型标定的统计严谨性（**这一节是"技术实现"的最高分点**）

> **核心方法论：三层递进，各司其职。强烈建议整节进方案书。**

```
[1a] 恒等式核查    → 证明"四维度分→总分"是定义式，不可作为效度证据（负向结论）
[1b] 维度分自洽性  → 检验维度分与上游位置变量的方向是否合理（唯一有信息量）
[1c] 权重支持度    → 客观赋权能否支持手拍权重（方向性参考）
[2]  回归诊断      → 单变量对应的系数 + BP/JB 诊断（HC3 稳健标准误）
[3]  λ 参数估计    → log-log 反解 λ 的 95%CI（参数敏感性参考，非效度）
```

#### 【1a】把"伪严谨"自己拆掉 —— **第一版方案被自己的实测证伪**

原设计想用"带约束 OLS 检验四维度分 → 总分的权重"，实测：

```
维度            OLS β       声明 w        差
客群匹配度      0.350359    0.3500    +3.59e-04
竞争压力        0.250292    0.2500    +2.92e-04
交通可达性      0.250231    0.2500    +2.31e-04
租金承受力      0.149301    0.1500    -6.99e-04
R² = 0.9999852189
```

**β 精确复原声明权重，R² ≡ 1。** 原因：`total = Σ(dim_score × weight)`（无截距加权和）。  
**用 OLS 去"检验"它，等于用回归去验证一个定义式。**

> **答辩金句（直接可用）**：  
> 「我们没有用回归去验证权重。因为总分的定义就是四维度分的加权和，用 OLS 回归它必然得到  
> β≡w、R²≡1——**这是定义式的算术结果，不是数据证据**。把它报成"回归验证了权重"是伪严谨。」

#### 【1b】唯一有信息量的检验：维度分自洽性

| 维度    | 上游变量   | 预期方向 | 实测 Pearson  | 结论        |
| ----- | ------ | ---- | ----------- | --------- |
| 客群匹配度 | 需求规模 D | 正    | **+0.5259** | ✅ p<0.001 |
| 竞争压力  | 捕获份额 P | 正    | **+0.8834** | ✅ p<0.001 |
| 交通可达性 | 最近同类距离 | 负    | −0.0532     | ✅ ns      |

> **"竞争压力 ↔ 捕获份额 = +0.8834"是这份分析里最有力的一个数** ——  
> 它直接印证了 `s = 60·P/p_ref` 的 Huff 份额映射在真实数据上成立。

#### 【1c】抑制效应（suppression）—— **主动规避，不是遗漏**

`corr(D, P) = −0.5111`（需求密集处竞品也密集）：

| 模型              | β(P)       | β(D)  |
| --------------- | ---------- | ----- |
| `竞争压力 ~ P`      | **+82.17** | —     |
| `竞争压力 ~ P + D`  | +82.17     | −0.42 |
| `客群匹配度 ~ P`     | **−63.84** | —     |
| `客群匹配度 ~ P + D` | **−49.10** | +0.88 |

**从 +82.17 掉到 −49.10，符号直接翻转。**  
⇒ **每个维度只对其对应的上游变量做单变量回归，禁止混放。**

#### 【2】竞争压力映射形式的完整检验（**最硬的一节，建议成页**）

被检验对象：`scoring.py:161` 的 `s = 60.0 * P / p_ref`（**手写的参数化假设，不是拟合出来的**）

**先净化样本（关键设计）**：三条分支必须隔离

| 分支       | 条件            | 行为                      | 样本数    |
| -------- | ------------- | ----------------------- | ------ |
| (a) 蓝海特例 | `n_comp == 0` | `return 75`，**完全绕过映射式** | 3      |
| (b) 硬截断  | `P > 0.6667`  | `min(100, ·)` 压平为 100   | 19     |
| (c) 正常映射 | 其余            | `s = 150P` 生效           | **61** |

> ⚠️ **不隔离 (a) 就会测错**：75 是常数，混进来会被当成"映射残差"污染统计量  
> （初版脚本就踩了这个坑，导致高区标准差被虚报成 8.78，实际应为 0）

**H1 线性假设：✅ 经检验成立**（未截断子样本 n=61）：

```
自由线性拟合 s = a + b·P （HC3 稳健标准误）
  a = 0.1200  SE=0.1416  t=0.848   p>0.999  95%CI = [-0.157, +0.398]
  b = 149.7356 SE=0.3450 t=434.053 p<0.001  95%CI = [+149.059, +150.412]

Wald  H0: b = 150  → W = 0.6798  p = 0.4097  不拒绝 ✅
Wald  H0: a = 0    → W = 0.8190  p = 0.3655  不拒绝 ✅

★ 逐点核对: 61/61 家精确等于 round(150·P)
```


**三条证据互相印证**：① `b` 的 95%CI 覆盖现状值 150 ② Wald 不拒绝 `b=150` 也不拒绝 `a=0`  
③ **61/61 逐点精确命中**——**不是"近似成立"，是零偏离**

> 第 3 条比任何拟合优度都硬：它直接排除了对数/分段/幂等更复杂形式的必要性

**H2 无饱和假设：⚠️ 被拒绝，但"修不了"——一个漂亮的数学结论**

**事实**：`P > 0.6667` 的 19 家门店竞争分**全部并列 100，标准差 = 0**，区分度归零。

**证明"保持低区不动的软饱和在数学上不存在"**：

```
希望同时满足:
  (i)   P = P* 处 s = 100      （与现状连续）
  (ii)  P > P* 处 s 单调不减
  (iii) 恒有 s ≤ 100

但 P* 处 s 已达上界 100。由 (ii)+(iii):
      s(P) ≥ s(P*) = 100  且  s(P) ≤ 100   →   s(P) ≡ 100   (P ≥ P*)
⇒ 同时满足 (i)(ii)(iii) 的唯一函数是常数 100。→ "保号软饱和"在数学上不存在。
```

**方案乙（全程 Hill 软饱和）实测参数**，参数化使 60 分锚点**精确保住**：

```
s(P) = 100·P^a / (P^a + c^a),  c = P_REF·((100−60)/60)^(1/a)
→ 任何 a 下 s(0.40) ≡ 60.00（锚点不破）
```

| a       | c      | s(.20) | s(.40)    | s(.667) | s(.85) | s(1.0) | 高区标准差 |
| ------- | ------ | ------ | --------- | ------- | ------ | ------ | ----- |
| 1.5     | 0.3053 | 34.65  | **60.00** | 76.35   | 82.29  | 85.57  | 3.268 |
| **2.0** | 0.3266 | 27.27  | **60.00** | 80.65   | 87.14  | 90.36  | 3.443 |
| 3.0     | 0.3494 | 15.79  | **60.00** | 87.41   | 93.50  | 95.91  | 3.003 |
| 4.0     | 0.3614 | 8.57   | **60.00** | 92.05   | 96.83  | 98.32  | 2.202 |

**结构判据（唯一不能被恒等式化的检验）**：控制 P 后，P 之外的变量还有没有增量解释力？

| 模型         | R²     | β_P     | p(β_P) | 额外β     | p(额外)      |
| ---------- | ------ | ------- | ------ | ------- | ---------- |
| 基准 `s ~ P` | 0.8948 | 104.253 | <0.001 | —       | —          |
| `+品牌力`     | 0.8973 | 104.120 | <0.001 | +2.5433 | >0.999 不显著 |
| `+竞品数`     | 0.8970 | 108.337 | <0.001 | +0.1786 | >0.999 不显著 |
| `+两者`      | 0.8990 | 107.709 | <0.001 | +2.2770 | >0.999 不显著 |

`ΔR²` 全部 `<0.005`，额外项全部不显著 → **竞争分的信息全部来自 P**，"纯 P 映射"的形式设定得到支持

**外部交叉验证**：`Spearman(s, P_anchor) = +0.8621`，`Spearman(s, P) = +0.9931`  
→ **映射形式不依赖品牌口径**

**最终建议：不改。理由四条**（这四条是"知道边界在哪"的体现）：

1. 低区已**逐点精确**成立，改写会破坏这一已验证的结论
2. 高区 `s` 无变异，**无从拟合**——高区分度只能靠 P 重新生成，属**设计决策而非数据发现**
3. 竞争分权重仅 **0.25**，且高 P 门店高度集中在同一商圈，跨商圈排序基本不受影响
4. 换 Hill 式会改变 60 分锚点的含义，牵动整条标定链

| 改动              | 竞争分          | 月流水净影响                | 离散度        |
| --------------- | ------------ | --------------------- | ---------- |
| **锚点修正**（B0→B1） | 因点位而异（−20~0） | **恒为 −30.4%**         | **0.0 pp** |
| **品牌溢价**（B1→B2） | **恒为 0**     | 因品牌而异（−5.3% ~ +13.4%） | 18.7 pp    |

- 锚点修正对**所有品牌所有点位一律 −30.4%、离散度 0.0pp** → **印证它是系统性 bug 修复，与品牌无关** ✅
- 品牌溢价的实测值与理论值 `(uplift−1)` **逐点位完全吻合** ✅
- `竞争分` 在 B1 与 B2 下**处处相等** → 品牌溢价确实不进竞争分，**符合设计** ✅

**⚠️ 诚实披露（未擅自改，挂"待裁决"）**：

- `REF_DP=6.2489` 数值每项都能复现，但它实&#x4E3A;**"剔除 6 个低证据点后 77 家"的中位**，  
  **不是注释写的"全样本中位"** → **错的只是注释里的出处与口径**
- `P_REF=0.5012` **复现不出来**：同口径可复现值 0.4997，引擎值高 **+0.0015（+0.3%）**，  
  量级很小，但说明这对常量**并非"同一次运行产出"**
- 处置：只改注释、**数值一个没动**（改锚点会改写全部历史结论，须用户拍板）
- 说明"竞品取数与口径修正"链条的完整性

### 3.7 样本扩量 83 → 796 家（×10）

- **根因**：不是数据不够，**是当初只手标了 3 个商圈**（in77 39 家 / 天一 27 家 / 海宁银泰 17 家）
- **关键洞察**：标定走的是 `data.query.query_within`——**纯本地 SQLite，不是高德实时**  
  ⇒ **标定样本的原始材料本来就在本地库里**
- **做法**：`expand_sample.py`（零 API）枚举 2,551 家可识别品牌奶茶店 → 商圈锚定（1km 内最近商圈 POI）  
  → 按引擎同口径算 D/P → 按品牌算 uplift
- **工程决定**：加 0.01° 分桶空间索引（否则 2,551 店 × 4 category = 上亿次三角函数跑不完）
  - **加速有没有偷改结果？** 由**硬性对拍**验证：`|ΔD| 最大 = 0.000e+00`、`|ΔP| 最大 = 1.110e-16`、  
    **83/83 家完全一致** ⇒ 没有第二套规则
- **结果**：n≥5 商圈门槛 → 119 个商圈 / 804 家 → 剔低证据点后 **796 家（×10）**
- **但扩样后结论动了吗？** `Spearman(原, 扩样) = +0.2857 (n=8)` → 排序基本不相关
  - **正确的读法不是"旧结论被推翻"，而是"旧点估计本来就不确定"**：  
    **7/8 个品牌的扩样点估计仍落在原 83 家的 bootstrap 95%CI 内**
- **诚实的混杂披露**：漂移**同时含"样本量增加"与"分组变细"两个因素（混杂，未分离）**
- 落点：`docs/瑞幸入表与样本扩量-实施记录.md`

### 3.8 加盟费三态（`0` 与 `None` 不许混同）

- **坑**：旧代码 `if fee:` → `0` 与 `None` 都走 else。于是对**瑞幸**——全市场最出名的"不收加盟费"品牌——  
  系统会答"暂无公开加盟费口径"。**那是假话，而且是最容易被用户当场戳穿的一类假话**
- **修法**：加盟费**三态** `amount` / `none`（明确不收）/ `unknown`（查不到）
- **第二处表面（红线 8 的典型案例，强烈建议写）**：  
  聊天提示改好了，但 `app_chainlit.py` 构造**投入表单 note** 那段仍是老的两态写法  
  ⇒ **聊天里说"明确不收加盟费"，同一个屏幕右下角的表单上却写"暂无公开加盟费口径"**
- **为什么静态断言没抓住**：§15 当时验的是 `get_join_fee()` 的**返回值**，而 `app_chainlit.py` 是**消费方**  
  —— **返回值对、消费方用错，断言照样全绿**
- **补的断言（这条设计很精妙，可写进方案书讲"如何测消费方"）**：
  - **顺序断言**：`jf.get('status')` 必须出现在 `jf.get('fee')` **之前**
  - 刻意**不用**字面断言（`"jf.get('fee'):" not in APP`）——新写法里 `elif jf and jf.get('fee'):`  
    本来就含这个子串（`elif` 里还带着 `if`），**字面查会自己打自己**
  - 实测偏移：`status@8460 < fee@8629 < 暂无@8916`
- 落点：`src/engine/brands.py::join_fee_status`；`src/ui/app_chainlit.py`

### 3.9 品牌级成本覆盖（物料率 32% → 36%）

- **坑**：奶茶品类 `MATERIAL_RATIO['奶茶']=0.32`，而瑞幸 2025Q3 CFO 披露**原材料占总净营收 36%**  
  （券商测算毛利率 63.8% 互相印证）。用 32% 会**低估成本 4 个点**，回本周期系统性偏短  
  —— **结论方向是错的**，不是"略偏乐观"
- **实测量级**（in77 / 月租 ¥20,000 / 35㎡）：

| 品牌   | 物料率           | 月物料     | 回本周期       |
| ---- | ------------- | ------- | ---------- |
| 蜜雪冰城 | 0.32（品类级）     | ¥39,802 | 21.4 月     |
| 瑞幸   | **0.36**（品牌级） | ¥44,777 | **27.0 月** |

**差 5.6 个月全部来自物料率那 4 个点** —— 这就是该坑的具体量级

- **设计原则**：**品牌级覆盖优先于品类级**；`get_material_ratio(cat, brand=None)` 不传 `brand` 时  
  行为与旧版**逐位相同**（向后兼容）
- 落点：`src/engine/utilities.py`

### 3.10 `月固定成本` 命名陷阱（**"同名不同义"的实战案例**）

- **问题**：`estimate_profit` 的 `fixed_cost` 变量累加的是**全部成本**（含物料/损耗/外卖抽成/场地附加/税  
  ——这些都是随流水变动的项），键名却写作 **`月固定成本`**，并被 UI 明细表、PDF 报表、规则解读文案  
  **直接展示给用户**
- **实测（宁波 30㎡ 奶茶 / 自报流水 8 万 / 蜜雪）**：

|                           | 金额          |
| ------------------------- | ----------- |
| 真固定成本（租金+人工+水电+摊销+品牌费+杂费） | **¥37,777** |
| 该键实际值（= 总成本 = 流水 − 净利）    | **¥78,336** |
| 倍差                        | **2.07×**   |

> 把总成本标成"固定成本"展示，会让店主**低估可变成本、误判盈亏平衡点**。

- **处置**：变量改名 `total_cost`；规范键 → `月成本合计`；`月固定成本` 保留为**兼容别名**（标记已废弃）；  
  三处用户可见标签改掉；回归哨兵断言 **`月成本合计 > 月固定成本 × 1.3`**（防有人再把两者当同一个数）
- 落点：`src/engine/utilities.py`

## 10. 关键答辩话术（**可直接背**）

### 10.1 被问"你的权重怎么验证的"

> 「我们没有用回归去验证权重。因为总分的定义就是四维度分的加权和，用 OLS 回归它必然得到  
> β≡w、R²≡1——**这是定义式的算术结果，不是数据证据**。把它报成"回归验证了权重"是伪严谨。  
> 我们做的是**维度分自洽性检验**：检验每个维度分与其上游位置变量的关系方向是否符合模型设定。  
> 实测三条全部通过，其中**竞争压力与捕获份额的相关系数达 +0.883**，直接印证了 Huff 份额映射在真实数据上成立。」

### 10.2 被问"你做了什么回归"

> 「做了单变量线性回归 + 完整诊断，所有模型用 **HC3 异方差稳健标准误**（因为 BP 检验拒绝了同方差）。  
> 我们**没有**做多变量混放，因为 D 与 P 实测相关系数 **−0.511**（需求密集处竞品也密集），  
> 混放会产生 suppression 导致符号翻转——我们实测到 β(P) 会从 **+82 翻到 −49**。  
> **这是刻意规避，不是遗漏。**」

### 10.3 被问"为什么不验证模型能预测营收"

> 「因为**因变量不成立**。我们用"外卖月售"作经营代理做过检验，实测与模型核心预测子 P 的相关是  
> **−0.229（p=0.037）**，方向与预期相反。在这个前提下做"选址分 → 营收"的回归，  
> 等于**拿一个已被自己证伪的因变量去拟合模型**。所以我们不做，而是把它明确列为后续数据扩充计划。」

### 10.4 被问"满分并列怎么办"（竞争分截断）

> 「竞争压力分采用线性映射 `s = 60·P/P_REF`，在 `P ≤ 0.667` 区间经检验**与数据逐点精确一致（61/61）**，  
> Wald 检验不拒绝斜率 =150。在 `P > 0.667` 区间采用满分封顶，导致约 23% 门店并列 100。  
> 我们评估过软饱和方案，但已证明"**保持低区不变的软饱和在数学上不存在**"——因为 `P*` 处已达上界 100。  
> 改用全程 Hill 软饱和会改变 60 分锚点含义、牵动全部标定，而竞争分权重仅 **0.25**、  
> 头部门店同商圈，**收益不足以偿付改模型风险**，故保留封顶并作为已知局限说明。」

### 10.5 被问"λ 为什么取 2.0，和你的估计对不上"


> 「log-log 形式反解出的 λ 是 0.55，95%CI 不覆盖 2.0。但这个式子与引擎的 Huff 形式不完全等价  
> （引擎式含竞争项求和），log-log 里只有一个距离弹性，是近似解读；更关键的是**这个回归的因变量  
> 仍是外卖月售**。我们用 λ∈[1.0, 3.0] 的敏感性检验证明结论不依赖 λ 的精确取值：  
> 全区间两两排名 Spearman 最低 **0.937**、Top10 重合度 **≥80%**。  
> 所以 **λ=2.0 取文献值是稳健性声明，不是参数标定。**」

### 10.6 被问"这和一张 Excel 有什么区别"

> 「三个时刻 AI 是唯一解：① **意图理解**——一句话解析出品类/地点/预算，无需填任何表单；  
> ② **专家视角切换**——9 位专家共享同一套引擎结论，只切换视角，问租金/问竞争/问加盟费得到  
> 不同专家的针对性解读，**而不是同一个答案**；③ **门头照片识别 + 口语化结论**——  
> VLM 识别装修/可见度/卫生，并把引擎的一堆数字**翻译成创业者听得懂的话**。」

### 10.7 30 秒路演（电梯陈述）

> 每年有几百万个体创业者，把积蓄押在"一次选址"上，却只有感觉和中介话术可用——  
> 而选址一签就是三年，**错了就回不了头**。
>
> 址南针用 Huff 引力模型，把一个地址拆成"需求池 × 捕获份额"，先算出这个位置能带来多少流水；  
> 再**倒推出你最多能付多少租金**；最后用**一票否决**拦住"位置好但账算不过来"的坑。
>
> **在签字之前，把一笔不可逆的账，先算清楚。**
